# 고속도로 계획 코드 안내

`planner.py`의 `HighwayLanePlanner.plan()`이 전체 판단 순서와 상태를 관리한다.
폴더를 나누어도 동일한 플래너 인스턴스와 메서드를 사용한다.

```text
highway/
├── planner.py                   # 전체 흐름·상태 전환
├── first_merge/                 # 1차 합류: 411 → 409
│   ├── merge.py                 # 진입·대기·변경·완료 단계
│   ├── follow_target.py         # 옆 차선 추종 타깃 선택·유지·속도
│   └── priority.py              # 기존 첫 합류 우선권 판단(보존)
├── driving/                     # 일반 고속도로
│   ├── lane_following.py        # 현재 차선 앞차 찾기·ACC
│   ├── lane_change.py           # 한 차선 변경 시작·유지·완료
│   └── obstacle_avoidance.py    # 정지 장애물 회피 경로
├── second_merge/                # 2차 합류
│   ├── priority.py              # 두 번째 합류 우선권·양보 속도
│   └── speed_limits.py          # 두 번째 합류 접근 속도·곡률 처리
└── common/                      # 여러 구간이 함께 쓰는 계산
    ├── lane_map.py              # 지도 링크·차선 매칭·이동 가능 방향
    ├── path_generation.py       # 후보 경로 생성
    ├── collision_check.py       # 미래 차체 충돌·차선변경 앞뒤 간격
    ├── merge_safety.py          # 두 합류 구간의 공통 안전 검사
    ├── merge_priority.py        # 합류 판단 호출·속도 제한 안정화
    ├── speed_limits.py          # 두 합류 구간의 곡률 속도 보정
    ├── object_motion.py         # 객체 이동·정지 상태
    └── types.py                 # 차선 매칭·후보·계획 결과 자료형
```

## 파라미터를 바꿀 때

설정은 **[config/parameters/highway.py](../../config/parameters/highway.py)** 한 파일이다.
1차 합류 → 일반 고속도로 → 2차 합류 → 공통 → 지도 → 자동 계산 순서이며,
각 구간 위쪽에 자주 튜닝하는 값을 배치했다. 모든 값 옆에 한국어 설명이 있다.

| 자주 조절할 값 | 현재 값 | 적용 |
|---|---:|---|
| `HIGHWAY_CRUISE_SPEED_KPH` | 60km/h | 일반 고속도로 최고 목표속도 |
| `ENTRY_MERGE_FRONT_GAP` | 2m | 411→409 최소 앞 범퍼 간격·추종 기준 |
| `ENTRY_MERGE_FOLLOW_RESERVE` | 0m | 첫 합류 추종 목표에 더하는 여유 |
| `ENTRY_MERGE_REAR_GAP` | 8m | 첫 합류 최소 뒤 범퍼 간격 |
| `ENTRY_MERGE_CRUISE_SPEED` | 10m/s = 36km/h | 첫 합류 준비 속도 상한 |
| `LANE_CHANGE_BUMPER_MARGIN` | 4m | 일반 차선변경 미래 앞뒤 간격 |

`SEARCH_FRONT/REAR`는 추종 타깃 선택 범위이며 최소 안전 간격과 다르다.
일반 고속도로 속도는 `HIGHWAY_CRUISE_SPEED_KPH`만 수정한 뒤 재실행하면 된다.
일반 주행과 고속도로 검증 실행 모두 이 값을 런타임의 `high_speed_to_tollgate` 구간에 적용한다.
`--speed-cap-kmh`를 명시했을 때만 그 값과 비교해 낮은 값을 적용한다.
고속도로 밖 기본 속도, 횡단보도 제한, 합류 전용 속도·곡률·위험 제한은 유지한다.
공통 안전 검사와 앞뒤 접근속도 검사도 함께 적용된다.
`ASSUME_HIGHWAY_VEHICLES_KEEP_LANE=True`는 고속도로 차량이 차선을 변경하지 않는
검증 조건이다. 지도에 매칭된 고속도로 객체의 횡방향 위치를 유지해 예측하며,
검출 방향 오차만으로 옆 차가 자차 차선에 진입한다고 외삽하지 않는다.
현재 차체 겹침, 자차 차선변경, 도로의 실제 합류, 지도 미매칭 객체 검사는 유지한다.
끼어드는 차량이 있는 환경에서는 이 값을 `False`로 바꿔야 한다.
`first_merge/priority.py`는 호출 경로가 남아 있어 삭제하지 않았다.
미사용 설정 9개와 비활성 투영 진단 코드만 정리했으며, 기존 값·계산식·판단 순서는 유지했다.

## 기존 주행 정책 및 로그

일반 좌우 차선 변경은 시작 속도를 저장하되, 이를 고정 상한으로 묶지 않는다.
기존 경로의 남은 곡률과 앞뒤 차량을 가속 궤적으로 다시 검사해 통과하면 재가속한다.
낮은 속도로만 통과 가능한 틈이나 급한 회피 경로는 시작 전에 거절하며,
변경 도중 목표속도를 단계적으로 낮추는 탐색은 적용하지 않는다.
원래 차선의 ACC·곡률 제한으로 변경 중 감속하지 않으며, 새 전방 위험에 대한
제동·신호·구간 제한속도·센서 무효 처리는 유지한다. 정지 상태에서 시작할 때는
경로에 맞는 양의 출발 목표속도를 검증한다. `lane_change_cruise`에 진입 속도,
현재 목표속도, 가속 거절 사유를 기록한다. 아래 411→409 추종 합류 정책과는 별개다.

411에서는 y=251.20부터 409의 앞뒤 간격·접근속도·변경 완료까지의 충돌을 검사한다.
안전한 틈이 있으면 즉시 시작하고, 막혀 있으면 현재 차선을 따라 한 번 감속해 대기한다.
409의 앞 30m·뒤 15m 범위에서 가장 가까운 차량을 선택하고, 나란히 달리거나 뒤에 있는
차량이면 411에서 속도를 조절해 먼저 보낸다. 선택한 차량은 더 가까운 검출이 나타나도
교체하지 않는다. ID 변경은 위치·속도·방향이 일치하는 유일한 후보만 재연결한다.
합류 시작 앞차 여유는 범퍼 기준 2m, 추종 추가 여유는 0m다. 차체 길이와 접근속도에
따른 여유는 별도 포함한다. 범위를 벗어난 차량도 기존 전체 충돌 검사에는 남는다.
변경 거리도 도로 제한속도가 아닌 실제 합류 목표속도로 정한다. `motion_state=uncertain`은
검출 실패가 아니라 추적 이력이 아직 짧다는 뜻이다. 유효한 속도가 있으면 그 속도로
ACC와 미래 위치를 계산하며, 미확정이라는 이유만으로 정지 궤적을 추가하지 않는다.
실측 속도 0인 차량과 속도값 자체가 없는 차량의 보수적 검사는 유지한다.
떠나는 차선의 차량도 실제 차체 충돌 검사에는 남는다.
목표 차선 앞뒤 차량의 간격 검사는 유지한다.
합류 준비 속도는 최대 36km/h이며, 필요한 감속은 진입차선에서 먼저 끝낸다.
옆 차선이 비어 보여도 60km/h로 가속하며 긴 변경 경로를 잡지 않는다. 합류 완료 후에는
2초 동안 같은 추종 제어로 연결한 뒤 일반 도로 속도 계획으로 돌아간다.
최종 경계는 링크 끝 y=89.20이 아닌 **y=140**이다. 대기 위치는 약 y=169이며,
경계 전에 변경을 완료할 22m와 차체·추가 여유를 확보하기 위한 위치다.
진입차선에 장애물이 있으면 그보다 먼저 대기해 옆으로 빠져나갈 공간을 남긴다.
대기 중에는 매 판단 주기 재검사하며, 합류 시작 후에는 경로·추종 대상을 유지한다.
속도는 고정하지 않고 선택한 앞차의 간격·속도에 연속적으로 맞춘다. 실제 앞차 급제동이나
새 장애물은 안전 검사가 우선한다. 실제 정지/속도 누락 객체는 정지거리 기반 상한을 적용하며,
가까운 충돌 위험은 즉시 제동한다. 미확정 객체를 통째로 무시하지 않는다.
시작 전 전체 변경 궤적을 검사하고, 시작 후에는 남은 변경과 정렬 시간을 다시 검사한다.
변경이 끝나가는 순간에도 매번 5초 이후의 추종 상황까지 다시 합류 조건으로 적용하지 않는다.
실제 전방 충돌 위험·보행자·신호·센서 무효에 따른 제동은 유지한다.
완료 후 409를 유지하고, 409→411 복귀는 금지한다. 409→410은 기존 안정화·안전검사 후
별도의 한 차선 변경으로 허용한다.
첫 합류의 공통 후속 링크 420에 차체와 여유 거리까지 진입하면 합류 양보 검사를 종료한다.
이후에도 일반 ACC·차체 충돌·차선변경 안전검사는 계속 적용한다.
409에서 미리 차선을 바꿨다는 이유만으로 실제 합류 지점의 검사를 생략하지 않는다.

튜닝은 `src/config/parameters/highway.py`의 구간별 주석을 따른다.
설정 모듈을 직접 가져오므로 이 폴더에는 중복 `parameters.py`를 두지 않는다.
`config/parameters/sections.py`에는 고속도로 활성 영역과 종료 우회전 영역이 있다.

실행 결과는 `AIM2026/outputs/expert/<실행 이름>/`에 남는다. `control.jsonl`의
`planning.entry_merge`에는 단계, 후보 거절 사유, 목표속도, 충돌 예측이 기록된다.
`lead_id`, `lead_gap`, `desired_gap`, `target_event`는 실제 추종 대상과 간격 판단이다.
RViz ROI/지도 화면 모두 노란 테두리로 탐색 범위, 빨간 차량으로 실제 추종 대상을 표시한다.
탐색 범위는 409 지도 구간 안으로 잘리며 모델 인지 ROI(하늘색)와 별개다.
이 로직은 411→409 및 완료 직후 인계에만 적용한다. 두 번째 합류는 변경하지 않는다.
411→409 후보의 초기 앞뒤 간격과 변경 중 미래 간격은 `ENTRY_MERGE_FRONT_GAP` /
`ENTRY_MERGE_REAR_GAP`을 사용한다. 일반 차선변경은 `LANE_CHANGE_BUMPER_MARGIN`을 유지한다.
뒤차 접근속도에 따른 추가 여유와 차체 충돌 검사는 두 경우 모두 유지한다.
간격 거절 로그의 `gap`, `required_gap`, `gap_policy`로 적용 기준을 확인할 수 있다.
`inference_age_ms`와 `control_dt_s`로 인지 지연과 제어 주기를 함께 확인할 수 있다.
`inputs.jsonl`은 인지 객체 원본, `inference.log`는 추론시간과 센서 상태를 담는다.
인지 입력의 차량 속도는 `AIM2026/Inference/main.py`에서 LiDAR 센서 시각에 정렬한다.
50ms 이내 과거 상태가 없을 때만, 이미 수신한 두 상태가 해당 시각을 감싸고 간격이
100ms 이하이면 속도를 보간한다. 외삽과 센서 만료시간 연장은 하지 않는다.
이 처리는 인지 입력에만 적용하며 GPS/DR 위치 추정 및 제어용 자차 상태 스트림은 유지한다.

시작 전 충돌 원본은 `before_placement.json`에 보관한다. 기존 `Ego` 또는
`Ego, -100` 기록과, 현재 actor 목록에서 제거된 것이 확인된 이전 NPC 번호만
초기 잔여 기록으로 구분한다. 새 충돌이나 사라졌다 다시 나타난 충돌은 중단한다.
같은 NPC 번호가 다시 생성되거나 actor 조회가 실패하면 해당 예외도 해제한다.
`--strict-collisions`는 이 초기 예외를 적용하지 않는다. 이 처리는 시나리오 검증부에만
있으며, actor 정보가 인지·판단·제어 입력으로 전달되지는 않는다.

`contact_events.jsonl`은 초기 잔여 기록(`startup_residual`), 새 보고(`new_report`),
재등장(`reappeared_report`), 초기 예외 해제(`startup_exemption_revoked`)를 구분한다.
새 충돌 보고 시 제어를 먼저 정지하고, NPC 정리 전에 `collision_stop.json`에
주행 경과시간·자차 위치·원본 ID·초기 기록·대상 actor 상태를 저장한다.
기록 시각은 관측 시각이며 실제 접촉 시각은 알 수 없다. 대상 상태는 정지 요청 후
조회한 정보이므로 그 위치만으로 실제 충돌을 부정하거나 정지를 해제하지 않는다.
