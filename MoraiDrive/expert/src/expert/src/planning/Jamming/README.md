# Jamming 구간 후보 경로와 장애물 회피

사진의 시작 ENU `(31.42, -486.50, 29.91)`에서 종료 ENU
`(-84.01, -547.78, 30.02)`까지 사용하는 구간입니다. 구간 설정은
`section.json`, 사용할 후보 목록은 `routes.json`에 있습니다.
현재 `jamming_01.csv`부터 `jamming_09.csv`까지 **9개 모두** 사용합니다.
`후보 전역경로/`의 원본은 보존하고, `공통종료선 경로/`에 끝을 맞춘 사본을 저장합니다.
사진의 밝기 경계 표시 좌표 `(-80.10, -546.66)`를 기준으로, 모든 경로의 실측 구간이
겹치는 종료선까지 자릅니다. 04번 기록이 먼저 끝나므로 실제 종료선은 사진 표시보다
진행 방향으로 약 **0.81m 전**, 시작점 기준 진행 거리 **125.899m**입니다.
각 사본의 마지막 점을 이 가로선에 보간하여 횡방향 위치를 유지합니다.
03·05번의 종료 직전 후진 샘플은 공통선 뒤쪽에 있어 잘려 나가며, 남은 구간은
다른 경로와 동일한 연속성·진행 방향 검사를 통과해야 합니다.

## 경로 기록

Expert(main.py)는 종료하고 ROS bridge는 유지한 상태에서 MORAI의
Manual-Keyboard로 직접 운전합니다. 기록기는 차량 제어를 발행하지 않습니다.

```bash
cd /mnt/c/Users/dydwn/AIMDrive/MoraiDrive/expert
source /opt/ros/noetic/setup.bash
source devel/setup.bash
/usr/bin/python3 record_static_route.py --check
```

1. 현재 ENU와 저장할 파일 경로가 출력됩니다.
2. 첫 사진의 시작점을 지나는 **가로 출발선** 근처에서 **Enter**를 누르면
   기록을 시작합니다. 구간 진행 방향에 수직인 선으로, 기준점에서 좌우 각각 12m,
   출발선 뒤 20m부터 앞 5m까지 허용합니다. 좌우로 다른 위치에서 후보를 기록하거나
   출발선에 도착하기 전부터 접근 구간을 함께 기록할 수 있습니다.
3. 원하는 후보 경로를 직접 주행하고, 두 번째 사진의 종료점을 지나는 가로 종료선에서
   **Ctrl+C**를 한 번 누르면 저장합니다. 종료선 앞뒤 5m, 좌우 각각 12m까지 허용합니다.
   횡방향으로 다른 위치에서 끝나도 되며, 전역경로 복귀 연결은 플래너가 별도로 검증합니다.
4. 같은 출발선으로 돌아와 명령을 반복합니다. `jamming_01.csv`,
   `jamming_02.csv`처럼 빈 번호를 자동으로 사용하며 기존 파일은 덮어쓰지 않습니다.

저장 위치:

```text
planning/Jamming/
├── section.json
├── routes.json
├── 공통종료선 경로/       # 플래너가 읽는 정렬된 9개 CSV
└── 후보 전역경로/
    ├── jamming_01.csv
    ├── jamming_01.status.json
    ├── jamming_02.csv
    └── jamming_02.status.json
```

`--check`는 좌표 출력 후 기록을 기다리는 명령으로 변경했습니다.
좌표만 확인하고 종료하려면 `--check-only`, 파일명을 직접 정하려면
`record_static_route.py right_01`을 사용합니다.
이전 정적장애물 구간은 `--section static`으로 선택합니다.

좌표 출력의 `forward`는 출발선에서 앞뒤로 떨어진 거리, `right`는 기준점에서
좌우로 떨어진 거리입니다. 양수는 각각 전방·오른쪽, 음수는 후방·왼쪽입니다.
출발선 설정은 `section.json`의 `approach_distance_m`(뒤쪽 허용 거리),
`start_longitudinal_tolerance_m`(앞쪽 허용 거리),
`start_lateral_half_width_m`(좌우 허용 거리)이며, 녹화 시작과 후보 등록에 동일하게
적용합니다. 좌우 범위는 `activation_half_width_m` 안으로 설정해야 합니다.
`--start-x`, `--start-y`, `--start-radius`는 기존 static 구간 전용입니다.
종료선은 `end_longitudinal_tolerance_m`(앞뒤 허용 거리)와
`activation_half_width_m`(좌우 허용 거리)을 사용합니다.

`/Ego_topic`의 원본 ENU와 heading을 약 0.2m 간격으로 저장합니다.
열은 `x,y,z,heading_deg,yaw_rad,s_m,speed_mps,source_stamp_s`입니다.
시작·종료 위치, 좌표 연속성, 진행 방향 검사를 통과한 기록만 `routes.json`에
자동 등록합니다. 중간에 끊긴 파일은 보관하되 후보로 등록하지 않으며,
동명의 `.status.json`에 `ready_for_planner`와 오류 이유를 남깁니다.
현재 정렬 모드에서는 새 후보 등록 시에도 공통 종료선 사본을 다시 생성하고 검증합니다.
기존 원본의 오류 기록은 `.status.json`의 `original_recording_error`에 남습니다.

같은 사진 기준으로 원본 전체를 다시 정렬하려면:

```bash
cd /mnt/c/Users/dydwn/AIMDrive/MoraiDrive/expert
PYTHONPATH=src /usr/bin/python3 -m expert.src.planning.Jamming.prepare_routes --end-enu -80.10 -546.66
```

## 회피 실행 구조

```text
수동 주행 → /Ego_topic → 원본 CSV → 공통 종료선 절단·검증 → routes.json
                                                           ↓
Expert → LatticePlanningProcess → JammingPlanner → 기존 RecordedStaticPlanner
                                   ↓                       ↓
                      ENU를 구간 진행축 좌표로 회전    후보 연결·차체 충돌 검사
                      차량·경로·장애물·방향 함께      곡률·속도·전역경로 복귀
                                   ↑                       ↓
                                   └── ENU로 되돌린 회피 경로 → 기존 제어기
```

`정적장애물/recorded_planner.py`와 `corridor_graph.py`의 탐색·충돌 검사·
속도·추종 로직을 공유합니다. 기존 구간은 북쪽(+Y)으로 진행하므로,
Jamming에서는 시작→종료 방향이 로컬 +Y가 되도록 좌표와 방향만 회전합니다.
거리·차량 크기·장애물 크기는 변하지 않고 원본 CSV도 그대로 보존합니다.

Jamming 구간의 정적장애물 GT를 받으면 진입 20m 전까지 기다리지 않고
백그라운드 계획을 시도합니다. 완성된 경로는 진입 전부터 보관하고, 접근 범위
(시작선 전 100m, 좌우 12m)에 들어오면 RViz에 선택 회피 경로 한 개를 표시합니다.
회피 경로는 녹화 시작선 **20m 전의 접근 구간부터** 포함해 검증합니다.
접근 구간에 들어오면 완성된 회피 경로를 추종하고, 이미 구간 안에서 Expert를 켰으면
현재 측정 위치부터 연결 경로를 생성합니다. 검증된 회피 경로를 추종할 때에는 기존
ACC가 정적장애물을 보고 중복 제동하지 않습니다. 녹화 시작선까지 전역경로로만
접근하다가 ACC에 막혀 시작선을 넘지 못하는 대기 상태를 제거했습니다.
후보 9개의 연결 탐색은 ROS 제어 루프와 병행할 때의 여유를 위해 8초까지 허용하며,
반복되는 곡선 상태·통로 경계 계산은 동일한 입력에서 재사용합니다.
설정된 전역경로 복귀점 10m 전에서 후보를 동일한 선으로 보간해 연결을 시작하고,
종료점 이후 전역경로 10m까지 검증합니다. 따라서 Expert의 전체 전역경로가
해당 종료점 이후까지 있어야 합니다. 설정된 폭 12m는 구간 활성화 범위이며,
실제 회피 가능 범위는 기존과 동일하게 기록한 후보와 전역경로에서 계산합니다.

후보 녹화를 모두 마친 뒤 **Expert를 재시작**하면 새 목록을 읽습니다.
후보가 없거나 유효한 회피 경로를 찾지 못하면 장애물이 있는 구간에서 정지합니다.
장애물이 없으면 기존 전역경로를 사용합니다. 이 폴더는 해당 구간의 장애물
회피 설정이며, GPS 수신 단절 시 위치 추정 기능을 추가한 것은 아닙니다.

## 동적장애물 대응

`Object_topic`의 속도는 기존 ROS 수신부에서 km/h → m/s로 변환합니다.
Jamming 안에서는 속도 절댓값이 0.05m/s 이하인 차량·정적 물체를 정적으로
분류합니다(정지 GT의 미세 오차 허용). 원본 메시지의 `is_static` 출처와 관계없이
정지 NPC도 기존 정적 플래너로 처리하며, 기존 정적 탐색·충돌 여유·속도 정책은 유지합니다.

`dynamic_planner.py`는 검증된 정적 경로 위에 다음 판단만 추가합니다.

1. 현재 명령 경로 앞 50m 내의 느린 이동 장애물을 만나면 횡방향 회피를 먼저 탐색합니다.
   기록된 통로의 차체 경계, 기존 정적장애물, 곡률을 그대로 검사하고, 현재 자세에서
   옆으로 이동한 후 원래 경로로 복귀하는 연결을 만듭니다.
2. 이동 물체의 위치·heading·속도로 미래 위치를 예측합니다. 고속도로 플래너의
   OBB 겹침 판정과 가감속·제어 지연 모델을 재사용해 옆 통로 차량과 복귀 과정까지
   검사합니다. 유효한 후보를 찾지 못하면 다음 제어 주기에도 탐색을 계속합니다.
3. 회피가 불가능하면 고속도로의 거리 유지 ACC 계산으로 앞차를 추종합니다.
   경로를 확정한 뒤에도 최신 GT로 앞차 간격과 충돌을 매번 다시 검사합니다.
4. **움직이는** 물체와 1초 이내 예측 OBB 충돌이면 목표 속도를 0으로 낮춥니다.
   그보다 먼 위험은 먼저 감속합니다. 이전의 0 목표 속도를 저장해 유지하지 않으므로
   위험이 해소되면 다음 주기에 주행 목표를 복원하고 기존 가속 제한에 따라 출발합니다.
5. GT 속도가 정지↔이동으로 바뀌면 해당 구간의 계획을 새 분류로 재생성합니다.
   정적 물체에는 이 동적 긴급제동 판단을 적용하지 않습니다.

차량 속도 판단은 이 플래너가 담당해 기존 ACC가 원래 직진 경로를 보고 중복 정지시키지
않도록 했습니다. 신호·보행자 처리는 기존 제어기에 남습니다.
RViz에는 실제 선택 경로와 `JAMMING: DYNAMIC AVOID / FOLLOW / AVOID_FOLLOW /
YIELD / EMERGENCY / CLEAR` 상태, 목표 속도, 앞차 간격, 예측 충돌 시간이 표시됩니다.
동적장애물만 있을 때는 최대 30km/h이며 기존 곡률·통로·제어 속도 제한도 함께 적용됩니다.

동적 횡이동 연결에는 차체 경계 여유 25cm를 추가합니다. 이미 확정된 동적 회피를
추종하다 녹화 기반 경계를 약간 벗어난 경우에는 `dynamic_recovery.py`가 실제 자세에서
기존 정적 경로로 돌아오는 연결을 다시 검증합니다. 정지·저속(0.6m/s 이하), 경계 초과
10cm 이하이고, 계획상 초과가 증가하지 않으며 첫 1m 안에 차체가 경계 안으로 들어오는
경우만 0.5m/s 이하로 복구합니다. 정적 OBB 충돌 여유와 곡률 제한은 유지합니다.
실제 추종 시에는 초기 초과량에 고정 5mm의 조향 응답·GT 오차 여유만 허용하며 매 주기
검증합니다. 기존 정적 플래너의 경계는 넓히지 않습니다. 복구 중에도 동적 충돌 제동은
유효하며, 통과하지 못한 복구는 출발시키지 않습니다. RViz의 `RECOVER`는 이 저속
복구이며, `BLOCKED` 아래에는 `recorded_envelope` 등 실제 정지 원인이 표시됩니다.
동적 경로의 추종 오차 또는 남은 경로 충돌도 정지 상태로 고정하지 않습니다.
현재 자세에서 기존 회피 경로와 원래 정적 경로로 재연결을 시도하고, 둘 다 불가능하면
기존 백그라운드 작업자에서 기록된 통로를 다시 탐색합니다. 완성된 경로는 최신 GT로
다시 검증한 후 적용하며 실패한 탐색도 재시도합니다. 신호·보행자 등의 기존 정지는 유지됩니다.

## RViz에서 생성된 회피 경로 확인

기존 Expert를 재시작한 상태에서 별도 WSL 터미널로 실행합니다.

```bash

source /opt/ros/noetic/setup.bash
source devel/setup.bash
rviz -d src/expert/rviz/jamming.rviz
```

기존 정적장애물 시각화와 같은 `/lattice/paths`, `/lattice/objects`를 사용합니다.
생성된 선택 회피 경로는 **빨강**, 정적장애물은 **주황 박스**, 차량은 **노랑**이며,
차량 위에 `JAMMING: RECORDED`와 계획 상태·선택한 경로 이름이 표시됩니다.
후보 라이브러리 9개를 화면에 나열하지 않습니다. 기존 `lattice_planner.rviz`에서도
같은 경로가 보이며, 새 설정은 선택 경로·장애물·차량만 표시하고 처음부터 Jamming 구간을 바라봅니다.
