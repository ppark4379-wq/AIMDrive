# 수동 후보 경로 기록

## 진입 사전 계산과 속도 정책 (2026-09-19)

GT 장애물이 들어오면 구간 진입 전에 회피·복귀 경로와 속도 제약을 계산합니다.
정지 후 계산하던 조건과 고정 10 km/h 제한은 제거했습니다. 현재 정책과
검증 범위는 [주행 정책 설명](../../../../../docs/driving_policy_20260919.md)을
참조하세요. 아래 2026-09-16 항목은 이전 정책의 변경 기록입니다.

단순 회피의 기록·지도 굴곡은 최대 5 cm 이내에서 평활화한 뒤 충돌·차체 경계를
재검사합니다. 복귀는 짧게 끝내는 후보보다 20 km/h 기준 감속이 적은 후보를
우선하여 복귀 중 추가 제동을 줄입니다. 원본 기록과 실제 충돌 여유는 유지하며,
설정은 `lattice_planning/parameters.py`의 `STATIC_PATH_*` 항목에 있습니다.

## 지그재그 장애물 탐색 (2026-09-16)

- 실제 방향이 계획보다 늦게 돌아 `ego_collision`으로 멈추던 상황을 수정했습니다.
  방향 오차 1.5~3도 또는 횡방향 오차 0.1~0.2m 사이에서는 오차가 커질수록 목표
  상한을 10~3.6km/h로 점진적으로 낮춥니다. 방향 오차 3도 이상이나 횡방향 오차
  0.2m 이상, 실제 보정 경로 추종 중에는 3.6km/h(1.0m/s) 제한을 유지합니다.
  방향 오차 0.75도 미만과 횡방향 오차 0.05m 미만을 함께 만족하면 보정 감속을
  상태를 해제합니다. 상태가 남아 있어도 작은 오차에 3.6km/h를 강제하지 않습니다.
  횡방향 오차는 경로 선분에 투영해 계산하고, 방향도 투영 위치의
  접선을 보간합니다. 경로 점 간격 때문에 생기는 종방향 거리는 보정 오차로 세지
  않습니다. 기존 0.75m 추종 이탈 정지 및 차체/충돌 검사는 별도로 유지합니다.
- 곡률 0.08/m를 조금 넘었다고 무조건 3.6km/h로 제한하지 않습니다. 곡률 0.08~0.18/m
  구간에서는 곡선 목표속도를 10~3.6km/h 사이로 연속 보간하고, 0.18/m 이상은
  3.6km/h로 제한합니다. 3m 전방 여유와 감속도 2m/s2를 반영해 앞쪽 제한을 현재
  위치까지 역산하므로, 급커브가 갑자기 미리보기 범위에 들어와 속도를 꺾는 현상을
  줄입니다. 곡률 기반 횡가속도 제한도 유지하며, 가속은 기존 1.2m/s2로 제한합니다.
- 완만하고 추종 오차가 작은 구간의 목표 상한은 `TRACKING_SPEED = 10.0 / 3.6`
  (10km/h)입니다. 급커브·자세 보정 시에는 `ALIGNMENT_SPEED = 1.0`(3.6km/h)을
  유지합니다. 두 값은 최저속도 강제가 아니며 충돌·신호·경로 끝의 감속 및 정지는
  유지합니다. 보정 허용 속도 조건은 `ALIGNMENT_SPEED`에 0.2m/s를 더해 맞춥니다.
- `[STATIC]` 로그의 `speed_policy_reason`은 `tracking`/`curvature`/`alignment`/
  `recovery`/`path_end`/`blocked` 중 실제 제한 원인을 표시합니다. `preview_curvature`,
  `cross_track_error_m`, `alignment_slow`, `tracking_speed_limits`를 함께 기록하여
  신호·ACC 제한과 곡률·자세 보정 제한을 구분할 수 있습니다.
- 실제 차체에는 기존 `COLLISION_MARGIN=0.5m`를 그대로 적용합니다. 계획용 추가
  `STATIC_TRACKING_MARGIN=0.1m`만 침범한 경우, 3~8m 길이의 자세 보정 연결 전체와
  남은 경로를 재검사한 뒤 `recover_alignment` 상태로 저속 추종합니다. 연결은 2.5cm
  간격으로 검사하고 회전·이동에 대한 샘플 간 여유도 추가합니다. 기존 0.5m 영역을
  침범하거나 안전한 연결이 없으면 정지를 유지합니다. 장애물 검사를 끄지 않습니다.
- 새 지그재그 탐색은 차체와 녹화 영역 경계 사이에 추가 15cm 추종 여유를 확보합니다.
  기록된 영역이나 반대 차선을 넓히지 않습니다. 보정 뒤의 확정 경로는 그대로 유지합니다.
- 기존 6개 녹화 경로와 그 연결을 먼저 검사합니다. 이것으로 완주하지 못하면
  `corridor_graph.py`에서 중간 횡방향 위치와 차량 방향을 함께 탐색합니다.
- 한라대 `HL_VTD/src/planning/local/corridor_lattice.cpp`의 사전 전체 경로 탐색
  방식을 참고했습니다. 이 프로젝트의 ENU 좌표, 녹화 영역, OBB 검사기를 사용하며
  HL_VTD의 별도 지도나 좁은 안전 여유 설정을 가져오지는 않습니다.
- 전역경로 쪽 공간을 구간 중간에서도 사용할 수 있어, 오른쪽 회피 후 왼쪽으로
  돌아오는 지그재그 연결이 가능합니다. 영역은 녹화 경로와 기존 전역경로의
  차체 통과 범위입니다. 실제 차선 경계 지도는 아니므로 현장 주행 검증이 필요합니다.
- 전방 1m / 횡방향 0.1m 후보, 여러 방향과 2/3/4/6/8/12m 연결을 사용합니다.
  위치·접선·곡률을 맞춘 연결 전체를 0.1m 이하 Y 간격으로 검사합니다.
  차량 길이·폭·GT 장애물 OBB·기존 안전 여유를 유지하고, 추종 중 재검사에 쓰는
  추가 0.12m 여유도 경로 생성 시부터 확보합니다.
- 단일 경로와 전역 복귀 구간을 모두 확보한 뒤 출발합니다. 실행 중에는 선택한
  경로를 유지하며 신호 정지, 새 장애물, 실제 추종 이탈 검사를 해제하지 않습니다.
- 상세 로그의 `corridor_search.method=corridor_astar`, `status=complete`가 새 탐색
  성공을 뜻합니다. `timeout`은 제한 시간 내 미발견이지 통과 불가능의 증명은 아닙니다.
  탐색은 백그라운드에서 수행하며, 안전한 완주 경로가 없으면 출발하지 않습니다.

## 좌표 및 저장 형식

- `/Ego_topic`의 `morai_msgs/EgoVehicleStatus.position.x/y/z`를 그대로 저장합니다.
- 단위는 ENU 미터이며 기존 Expert의 map 좌표와 동일합니다. 원점 이동,
  UTM 변환, 범퍼/차축 오프셋, 지면 높이 보정을 하지 않습니다.
- 사진의 시작 위치는 대략 `(-59.65, -159.06, 29.96)`입니다. 기본적으로 XY가
  `(-59.65, -159.06)`에서 5m 이내인지 확인합니다. Z는 실제 수신값을 보존합니다.
- `heading_deg`는 수신 각도, `yaw_rad`는 기존 Expert와 동일한 라디안 변환입니다.
- `후보전역경로/<이름>.csv`: `x,y,z,heading_deg,yaw_rad,s_m,speed_mps,source_stamp_s`.
- 기본 샘플 간격 0.2m, 마지막 위치도 보존합니다. 변경: `--spacing 0.1`.
- 다른 시작점은 `--start-x X --start-y Y`로 지정합니다. 경로 자체를 이동시키지 않습니다.

## 기록 기반 사전 계획

`routes.json`에 선택된 6개 파일을 정적장애물 구간에서 사용합니다. `right_4.csv`와
미완성 `right_06.csv`는 제외하고 06은 `right_06_retry.csv`를 사용합니다. 원본 CSV는
보존하며 로딩 시 04의 초반 후진 5개 점, 06 재기록본의 1개 점을 제외합니다.
05에는 후진 구간이 없습니다. ENU 원점은 이동하지 않습니다.

정지선 접근 구간에서 정적 GT가 있으면 먼저 정지 상태를 확보하고 백그라운드에서
완주 경로를 계획합니다. 계획이 끝나기 전에는 진행하지 않습니다. 기록 경로를
그대로 쓸 수 없으면 전진 방향 그래프 탐색으로 안전한 부분들을 연결합니다.
연결부는 위치/접선/곡률을 맞추고 차량 길이 4.635m, 폭 2m 및 기존 안전 여유로
OBB 충돌검사합니다. 전역경로 복귀와 이후 10m 진행 경로까지 미리 확보합니다.
복귀 상한 지점은 ENU `(-59.97, -116.70, 28.37)` 부근입니다. 마지막 20m에서
장애물을 지난 뒤 전역경로로 이어지는 부드러운 복귀 연결을 미리 검사합니다.
연결부는 위치/접선/곡률을 맞추며, 기존 회피 앞부분은 유지합니다. 복귀가 먼저
완료되고 실제 횡오차 0.3m 이내, 방향 오차 10도 이내이면 상한 지점까지 기다리지
않고 전역경로를 사용합니다. 새 장애물이 있으면 조기 전환하지 않습니다.
XY 기준으로 판단하며 Z를 보정하지 않습니다. 신호/장애물 감속은 그대로 유지합니다.
전역경로가 일시적으로 없으면 미리 확보한 전역경로 구간을 유지합니다.
회피에서 전역경로로 전환될 때 목표속도 증가를 `STATIC_TARGET_ACCEL=1.2 m/s2`로
제한하고 Pure Pursuit 추종 거리를 점진적으로 늘립니다. 제동 요청은 지연하지 않습니다.
복귀 연결은 차체에 추가 0.2m 추종 여유를 확보합니다. 허용 경계는 차체 네 변을
5cm 간격으로 교차 계산하며, 드문 측면 샘플 때문에 생기던 경계 함몰을 제거했습니다.
완만하고 정렬된 회피 구간에서는 `TRACKING_SPEED=10.0/3.6 m/s`(10km/h) 이하로
추종합니다. 급커브·자세 보정 시에는 3.6km/h로 제한하고, 정렬 회복 및 전역경로
전환 후에는 위 가속 제한으로 자연스럽게 속도를 높입니다.
종료 Y 좌표만 지났다고 복귀를 강제하지 않으며 실제 위치/방향과 충돌 여부를 확인합니다.

선택 후에는 세계좌표 경로를 유지하므로 로컬 전역경로가 잠시 없어져도 회피를
계속합니다. 새로운 장애물이나 추종 이탈은 정지 사유이며, 움직이면서 다른 후보로
계속 바꾸지는 않습니다. 신호/동적장애물 제어는 유지됩니다. RViz에는 선택 경로
하나와 `STATIC: RECORDED` 상태 및 선택된 파일 이름이 표시됩니다.

주의: 도로 경계는 지도 차선이 아닌 **수동 기록의 차체 통과 범위**로 제한합니다.
기록 자체가 도로 밖이라면 자동으로 판별할 수 없습니다. 실제 MORAI 저속 검증이
필요하며, 이 도로의 북향 정적장애물 구간 전용입니다.

오프라인 검사(차량을 움직이지 않음):

```bash
python check_static_routes.py
```

이 검사는 저장된 장애물 장면을 사용하며 현재 MORAI 장면과 다를 수 있습니다.
새 설정 적용은 Expert를 종료하고 `python main.py`로 다시 실행합니다.
선택 경로는 프로세스 메모리에만 보존됩니다. 회피 도중 종료했다면 정지선 접근
위치로 차량을 되돌린 뒤 시작하세요. 중간 자세에서 새 연결을 검증하지 못하면
`no_complete_route`로 정지하며, 안전 검사를 생략해 출발하지 않습니다.
