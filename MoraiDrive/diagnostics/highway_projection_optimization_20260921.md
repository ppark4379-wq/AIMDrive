# 고속도로 차로 매칭 계산 최적화

## 변경 범위

`HighwayLaneMap.project()`의 선분 거리 계산을 NumPy 배열 연산으로 처리한다.
고정 지도에서 선분 시작점, 방향 벡터, 길이 제곱을 로딩 시 한 번 준비한다.
차량 위치와 투영 결과는 매 호출 새로 계산한다. 지도 형상은 기존
`cumulative_s`와 마찬가지로 로딩 후 고정이라는 전제를 사용한다.

모든 기존 유효 선분을 검사하고, 최소 거리 근처의 후보를 원래 스칼라
계산으로 다시 평가한다. 동일 거리에서는 기존처럼 먼저 나온 선분을 선택한다.
외부 링크와 예외 입력은 기존 계산으로 처리한다.

차로 선택 점수, 충돌 검사, 합류 판단, ACC, 조향, lookahead, dt,
제어 주기와 파라미터에는 변경이 없다.

## 처리 시간

Windows / Python 3.11.9 / NumPy 2.4.6, 동일 가상 입력을 기존·최적화
플래너에 번갈아 전달했다. 조건별 준비 2회 이후 30회의 중앙값이다.

| 주변 차량 | 기존 | 최적화 | 속도 향상 | 기존 / 최적화 p95 |
|---|---:|---:|---:|---:|
| 0대 | 15.224ms | 2.758ms | 5.52배 | 15.960 / 3.586ms |
| 5대 | 44.038ms | 8.647ms | 5.09배 | 45.268 / 10.822ms |
| 12대 | 94.979ms | 16.653ms | 5.70배 | 104.386 / 17.318ms |

측정은 `HighwayLanePlanner.plan()` 호출만 포함한다. 지도 로딩, 입력 생성,
ROS 통신, 전체 Expert 실행, RViz 및 MORAI 렌더링은 포함하지 않는다.
실제 주행에서 30Hz 달성이나 영상의 조향 진동 해소를 확인한 결과는 아니다.

재실행:

```bash
python3 MoraiDrive/diagnostics/benchmark_highway_projection.py --iterations 30
```

## 결과 동일성 검증

- 지도 꼭짓점 전체 및 난수 시드를 고정한 주변 위치 7,821개에서
  투영 좌표·거리·경로 진행거리·방향각이 기존 계산과 정확히 같았다.
- 링크별 시작·중간·끝에서 횡오차, 방향, 선호 차로를 바꾼 1,386개
  매칭 질의에서 선택 차로와 투영 결과가 같았다.
- 중복 점, 등거리 선분, 끝점 밖 위치, 경계 근처 값, 매번 바뀌는 차량 위치와
  동일 ID를 가진 외부 링크에 대한 회귀 테스트를 추가했다.
- 성능 측정 96프레임에서 전체 플래너 결과가 같았다.
- 기존 테스트의 플래너 출력 59개도 변경 전 HEAD의 `project()`와 비교해
  전체 결과의 해시가 같았다. 경로·후보·목표속도·판단 사유·진단 필드를 포함한다.

관련 기존 테스트 116개와 신규 테스트 4개를 검사했다. 신규 4개는 통과했다.
기존 테스트의 실패 8개와 오류 2개는 수정 전후 동일하다. 여기에는 기존
고속도로/보행자 기대값 실패 6개와, 현재 비활성화된 투영 진단 기능을
요구하는 테스트 4개가 포함된다. 이번 성능 변경에서 해당 동작을 수정하지 않았다.

회귀 테스트는 Expert 소스 경로를 Python 경로에 넣고 실행한다:

```bash
PYTHONPATH=MoraiDrive/expert/src python3 -m unittest discover \
  -s MoraiDrive/expert/src/expert/tests -p test_highway_projection_equivalence.py
```
