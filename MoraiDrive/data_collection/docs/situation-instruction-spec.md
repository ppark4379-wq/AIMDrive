# Situation instruction 전달용 명세

- 버전: `situation-instruction-spec-v1-draft`
- 작성일: 2026-10-01
- 수정일: 2026-10-03 — 모든 Zone의 instruction에서 거리 수치 표현 제외
- 범위: 정적 장애물, 동적 장애물, 회전교차로, 고속도로, 터널의 프레임별 라벨과 문장 생성 계약
- 상태: 대화에서 합의한 내용을 통합한 검토본. 자동 판정 알고리즘·임계값·라벨링 tool은 아직 구현하지 않았다.

## 1. 목적과 역할

저장된 expert 주행 기록으로 현재 행동을 판정하고, 해당 프레임의 객체 GT로 상황 문장을 생성한다.

> 자차 {위치}에 {객체}가 있다. {행동 지시}.

- 상황: 객체 종류와 자차 기준 위치만 기술한다. 거리 수치는 모든 Zone의 상황·행동 문장에서 제외한다. 차로·도로 형상, 예상 횡단 방향, 미래 등장 순서는 상황 문장에 넣지 않는다.
- 행동: 실제 expert의 행동을 명령형으로 표현한다. 목표 속도 수치와 행동 이유는 넣지 않는다.
- 거리 데이터는 대상 선택·행동 판정·검수에 사용할 수 있지만 instruction 문장에는 넣지 않는다. 문장 생성 규칙으로 고정 회피 시작 거리를 정하지 않는다.
- instruction은 보조 Situation Head의 학습 정답이다. 추론용 객체 GT 입력이나 직접 제어 명령이 아니다.
- 추론 시 Situation Head를 제거한다. 따라서 학습 중에도 LLM의 필수 입력으로 Situation GT 문장이나 제거될 Head의 전용 출력 `F_s`를 사용하지 않는다.
- 보조 loss가 공유 특징을 만드는 학습 가능한 모듈에 전달되도록 해야 한다. 구체적인 Head·loss·gradient 경로는 모델 구현 담당자의 범위다.
- Navigation/Zone/global path의 추론 제공 여부는 별도 모델 입력 계약으로 확인해야 한다. 이 명세가 해당 입력의 가용성을 추가로 보장하지 않는다.

## 2. Zone 정의

| zone | 구간 | 주요 행동·사건 |
|---|---|---|
| `static_obstacle` | 체크포인트 3~4 사이, 장애물 배치 기준 `route_path_index: 668` | 접근, 좌우 회피, 복귀, 통과 |
| `dynamic_obstacle` | 경로 index 753~1081, 체크포인트 4 이후~6 이전 | 보행자 양보, 정지 대기, 재개 |
| `roundabout` | 체크포인트 8→9 | 진입 양보, 합류, 추종, 급제동 대응 |
| `highway` | 체크포인트 10→13 | 추종, 차로 변경, 끼어드는 차량에 양보, 급제동 대응 |
| `tunnel` | 체크포인트 14→15 | 앞차 추종, 앞차 급제동 대응, 대기, 재개 |

구간은 원본 수집 당시 route/시나리오 정의에 연결한다. 정적 장애물의 668은 배치 기준점이며 Zone 전체 범위나 회피 시작 프레임이 아니다. NPC 활성화 범위와 자차 Zone 범위도 구분한다. 경계 포함 규칙·겹침 해소는 구현 설정으로 명시한다.

## 3. 사용할 저장 데이터

| 데이터 | 용도 | 주의점 |
|---|---|---|
| `frame_id`, `sensor_time_ns` | 프레임 식별과 정답 연결 | episode/run까지 포함해야 전역적으로 유일함 |
| `ego_pose`의 위치·yaw·speed | 상대 위치·거리, 주행 상태 판정 | 동일 프레임에 연결된 값 사용 |
| 객체 GT의 ID·위치·종류·속도·크기 | 상황 설명, 대상 추적, 행동 판정 보조 | GT 유효성 확인. 종류는 근거가 없으면 추측하지 않음 |
| 연속 자차 상태, dense Ego timeline | 시작·진행·복귀·제동 판정 | timestamp 간격 사용. 일정 FPS라고 가정하지 않음 |
| `waypoints` | 실제 미래 이동 결과 확인 | 계획 경로가 아니라 기록된 미래 위치. 현재 onset 자체를 의미하지 않음 |
| 기록/고정된 기준 경로·구간·차로 정보 | 일반 조향과 회피, 합류와 차로 변경 구별 | 행동 판정 전용. 상황 문장에 도로 정보를 추가하지 않음 |
| raw expert 제어·경로·이벤트 | 가능한 경우 행동 판정 보조 | 기록 존재와 센서 프레임에 대한 유효 시간 대응은 별도 확인 |

### 확인된 collector 구현

- `internal_sensor_record/morai_pretraining/sensor_record_manifest.py`의 `build_episode_manifest()`가 센서 파일, 자차 pose, 객체 GT, 미래 waypoint를 하나의 entry에 연결한다.
- `waypoint_at_sensor_time()`은 실제 Ego 위치에서 0.5~2.5초 미래 waypoint를 만든다. 이 간격은 수집/학습 target 정의이며 instruction의 행동 임계값이 아니다.
- 확인한 동적 장애물 lap 100의 최종 manifest는 215 entries이며 `asset_roles`, `ego_pose`, `objects`, `waypoints` 등을 포함한다.
- 같은 episode의 분석 목록에서 `expert_control` 1,959개는 source timestamp가 null, `expert_local_path` 1,944개는 source timestamp가 0이었다. 원본 payload는 보존되어 있지만 최종 entry에 제어 명령까지 연결되어 있다는 뜻은 아니다. 다른 episode에도 동일하다고 일반화하지 않는다.
- 별도 `sync_native_files` backend는 `ego_state_for_frame`과 `applied_control`로 measurement를 만든다. 두 backend의 저장 계약을 혼용하지 않는다.

## 4. 상황 정보와 문장 규칙

### 4.1 문장용 위치와 내부 거리 데이터

- 위치 기준: 해당 프레임 자차 pose 원점과 yaw. 좌우는 자차가 바라보는 방향 기준이다.
- 위치 어휘: 앞쪽 / 왼쪽 앞 / 오른쪽 앞 / 왼쪽 / 오른쪽 / 왼쪽 뒤 / 오른쪽 뒤 / 뒤쪽.
- 정적 장애물 상황 문장은 앞쪽 / 왼쪽 앞 / 오른쪽 앞 / 왼쪽 / 오른쪽만 사용한다. 자차 뒤에 있는 정적 장애물은 상황 설명 대상에서 제외한다. 다른 Zone의 차량 대상 범위는 이 정적 장애물 규칙으로 변경하지 않는다.
- 위치별 각도 경계는 미확정이다. 구현 담당자가 경계값과 경계 프레임의 흔들림 처리 방법을 버전 설정으로 기록한다.
- 내부 거리 데이터: 동일 좌표계의 자차 pose 원점과 선택한 객체 GT 위치 사이의 수평 직선거리. 문장 출력용 값이 아니다.

`distance_m = sqrt((object_x - ego_x)^2 + (object_y - ego_y)^2)`

- 원본 실수 거리는 내부 데이터로 보존한다. 문장용 거리 반올림이나 거리 placeholder는 사용하지 않는다.
- 종방향 거리, 차체 간 여유 거리, 경로 길이와 혼용하지 않는다.
- 객체 위치는 원본 토픽/API 기준점인지 보정된 학습용 중심인지 출처를 기록한다. 기존 builder의 `objects_for_entry()`는 보정된 `training_center_world_xy`를 사용할 수 있다. 원본 토픽 위치 기준의 내부 거리를 계산할 때 이를 무조건 같은 값으로 간주하지 않는다.
- 장애물/보행자의 움직임은 행동 판정에 사용할 수 있지만, 상황 문장에는 객체 종류와 현재 위치만 넣는다.

### 4.2 객체 종류와 대상

- 기본 어휘: 정적 장애물 / 보행자 / 차량. GT가 뒷받침하는 세부 종류만 사용한다.
- 모델 이름으로 성별·직업·행동 의도 등을 추측하지 않는다.
- 대상 ID는 추적용이며 문장에는 노출하지 않는다. 가능한 경우 생애 단위를 구분하는 `instance_key`를 사용한다.
- 객체가 GT에 존재하는 것과 현재 행동의 관련 대상인 것은 다르다. 관련 객체 선택 기준은 Zone·expert 반응을 고려하여 구현한다.
- Zone별 고정 주의 거리와 회피 시작 거리는 정하지 않았다. 실제 객체 선택 거리와 expert 행동 시작을 별도 처리한다.
- 사용 불가능한 GT와 확인된 객체 부재를 구분한다. GT 누락을 “장애물이 없다”로 표현하지 않는다.

### 4.3 문장 기호

- `{S}`: 유효한 관련 객체의 상황 문장. 뒤에 공백을 붙인다. 객체 상황을 설명할 수 없으면 생략할 수 있으나 행동의 유효성은 별도로 판정한다.
- `{객체}`: GT로 확인된 객체 종류.
- `{위치}`, `{위치1}`, `{위치2}`: 해당 프레임에서 계산한 자차 기준 위치.
- 거리 수치는 문장 기호에 포함하지 않는다.
- `{방향}`: 정적 회피에서는 현재 수행 중인 회피 경로 구간의 왼쪽 또는 오른쪽. 전체 회피 주행 동안 고정하지 않는다. 차로 변경에서는 해당 변경 이벤트의 방향이다. 순간 조향 부호나 현재 객체 좌우 위치만으로 결정하지 않는다.
- 목적 설명(“간격을 확보하도록”, “충돌을 피하기 위해”)과 수치 속도 지시는 넣지 않는다.
- 정적 회피 문장은 “오른쪽으로 회피해라” 수준이다. 시작·진행은 내부적으로 구분하되 같은 문장을 허용한다.
- 감속·급제동·정지 유지 자체가 핵심 사건인 다른 Zone에서는 해당 행동 표현을 사용한다.

## 5. 정적 장애물

**행동 라벨은 여러 장애물을 함께 고려한 전체 회피 경로의 수행 상태를 기준으로 한다.** 상황 문장에 설명할 객체 목록은 매 프레임 갱신한다. 객체별로 독립된 회피 시작 이벤트를 만들어내지 않는다.

> 대상 장애물이나 경로의 회피 방향이 바뀌더라도, 같은 회피 주행이 이어지는 동안에는 `avoiding`을 유지한다.

경로를 미리 생성한 시점과 실제 회피 주행 시작은 구분한다. 경로 재계산·경로 ID 변경만으로도 새 시작을 부여하지 않는다.

| 라벨 | 의미 | 근거 데이터 | 개념적 판정 조건 | Instruction 틀 |
|---|---|---|---|---|
| `approach` | 회피 대상에 접근, 회피 전 | 자차 궤적·객체 위치 | 대상에 접근하며 아직 해당 회피를 시작하지 않음 | `{S}현재 주행을 유지해라.` |
| `avoid_start` | 전체 회피 주행 시작 | 연속 자차 위치·heading·기준 경로·수집된 회피 경로(이용 가능 시)·객체 위치 | 여러 장애물을 고려한 전체 회피 주행이 실제로 시작된 최초 프레임. 단순 경로 생성 시점은 아님 | `{S}{방향}으로 회피해라.` |
| `avoiding` | 전체 회피 경로 수행 중 | 회피 이벤트·자차 궤적·경로·객체 위치 | 회피 시작 이후 우회 수행 중. 대상 변경·회피 방향 변경·중간 직진에도 유지 | 현재 구간이 좌우 회피이면 `{S}{방향}으로 회피해라.`; 직진 통과이면 `{S}현재 진행 방향을 유지하며 통과해라.` |
| `returning` | 전체 우회 후 전진하면서 기존 경로 복귀 | 대상 통과 여부·자차 궤적·기준 경로 | 전체 우회 수행을 마치고 전진하면서 기존 경로로 복귀 중. 중간 장애물 통과·중간 방향 변경·후진을 의미하지 않음 | `{S}전진하며 기존 주행 경로로 복귀해라.` |
| `completed` | 회피·복귀 완료 이벤트 | 자차 위치·heading·기준 경로 | 복귀가 완료된 최초 프레임 | `회피가 완료되었다. 주행을 이어가라.` |
| `pass_through` | 별도 좌우 회피 없이 통과 | 자차 궤적·객체 배치 | 전체 회피 주행이 활성화되지 않은 채 통과. 진행 중인 회피 경로의 중간 직진은 `avoiding` | `{S}현재 진행 방향을 유지하며 통과해라.` |
| `normal` | 진행 중인 장애물 대응 없음 | 자차·객체·판정된 이벤트 | 관련 대응이 없거나 완료 이벤트 이후 | `{S}주행을 이어가라.` |
| `unknown` | 행동 판정 불가 | GT 유효성·자차·객체 기록 | 대상·행동 근거 불충분 또는 일반 조향과 회피 구별 불가 | 유효한 상황만 생성. 행동 supervision 제외 |

### 정적 다중 객체 표현

| 적용 라벨 | 배치·행동 | Instruction |
|---|---|---|
| `avoid_start`, `avoiding` | 오른쪽 앞 두 장애물의 왼쪽으로 회피 | `자차 오른쪽 앞에 {객체1}, 오른쪽 앞에 {객체2}가 있다. 두 장애물의 왼쪽으로 회피해라.` |
| `avoid_start`, `avoiding` | 왼쪽 앞 두 장애물의 오른쪽으로 회피 | `자차 왼쪽 앞에 {객체1}, 왼쪽 앞에 {객체2}가 있다. 두 장애물의 오른쪽으로 회피해라.` |
| `avoiding` | 회피 중 두 객체의 현재 위치가 달라짐 | `자차 {위치1}에 {객체1}, {위치2}에 {객체2}가 있다. 두 장애물의 {방향}으로 회피해라.` |
| `avoiding` | 같은 전체 회피 경로에서 왼쪽 우회 구간 이후 오른쪽 우회 구간으로 진행 | `자차 {현재 대상 위치}에 {현재 대상 객체}가 있다. 오른쪽으로 회피해라.` |
| `avoiding` | 같은 전체 회피 경로에서 오른쪽 우회 구간 이후 왼쪽 우회 구간으로 진행 | `자차 {현재 대상 위치}에 {현재 대상 객체}가 있다. 왼쪽으로 회피해라.` |
| `pass_through` | 두 장애물 사이 통과 | `자차 {위치1}에 {객체1}, {위치2}에 {객체2}가 있다. 두 장애물 사이로 통과해라.` |

- 문장에 사용하는 객체 위치는 매 프레임 갱신하고, 행동 방향은 현재 수행하는 회피 경로 구간에 맞춰 갱신한다. 단계 라벨 `avoiding`을 유지한다는 것이 방향 문장을 고정한다는 뜻은 아니다.
- 두 장애물의 같은 쪽을 통과하는 현재 구간에만 “두 장애물의 {방향}으로 회피해라”를 사용한다. 서로 다른 쪽으로 우회하는 전체 경로를 하나의 방향으로 설명하지 않는다.
- 자차 뒤로 넘어간 정적 장애물은 상황 설명 대상 목록에서 제외한다. 이벤트 추적용 ID·과거 기록은 보존할 수 있지만 후방 객체 설명을 instruction에 넣지 않는다.
- `returning`에서 통과한 장애물이 뒤에 있고 다른 유효한 관련 대상이 없다면 `{S}`를 생략하여 `전진하며 기존 주행 경로로 복귀해라.`만 생성한다. 이는 GT 미검출이 아니라 설명 범위에서 제외한 경우다.
- 후방으로 넘어갔다는 사실만으로 회피·복귀 완료를 판정하지 않는다. 완료 여부는 자차 주행 기록과 이벤트 상태로 별도 판정한다.
- 한 장애물을 통과하면 남은 대상 중심으로 갱신한다. 대상 변경만으로 `avoid_start`를 재발급하지 않는다.
- 다음 장애물을 피하는 동작을 기존 경로 복귀로 오인하지 않는다.
- 장애물 사이에서 잠시 기준 경로에 가까워져도 전체 우회 수행 중이면 `avoiding`이다. `returning`은 전체 우회가 끝난 후의 복귀이며, `completed`는 그 복귀까지 끝난 첫 프레임이다.
- 실제 멈춘 프레임에 “회피해라/주행을 유지해라”를 강제하지 않는다. 정적 구간의 감속·정지를 별도 문장으로 표현할지는 추가 사용자 결정 사항이다. 그 전에는 충돌하는 행동 문장을 유효 정답으로 발행하지 않는다.

## 6. 동적 장애물

라벨링 범위: 현재 유효한 대응 대상인 보행자 N명. 인원수 상한을 2명으로 두지 않으며, 순차 등장·동시 대응에 같은 행동 라벨을 사용한다. 현재 runner의 `max_count: 2` 설정은 시나리오 생성 제한이지 라벨 스키마 제한이 아니다.

| 라벨 | 의미 | 근거 데이터 | 개념적 판정 조건 | Instruction 틀 |
|---|---|---|---|---|
| `approach` | 보행자 접근, 양보 전 | 자차·보행자 위치·주행 기록 | 한 명 이상 관련 보행자에게 접근하되 양보 시작 전 | `{P}현재 주행을 유지해라.` |
| `yield_start` | 보행자 양보 시작 | 연속 자차 속도·궤적, 보행자 위치·이동 기록 | 한 명 이상 보행자에 대한 양보 행동이 시작된 최초 프레임. 대상 ID·인원수 변경만으로 재부여하지 않음 | `{P}보행자에게 양보해라.` |
| `yielding` | 움직이며 양보 진행 | 자차·보행자 기록, 판정된 양보 이벤트 | 양보 시작 이후 이동하며 양보를 이어감. 대응 대상·위치·인원수가 바뀌어도 행동이 이어지면 유지 | `{P}보행자에게 양보해라.` |
| `waiting` | 한 명 이상 보행자 정지 대기 | 자차 속도·유효 대응 보행자들의 위치·이동 기록 | 보행자 양보 중 자차가 정지 상태임. 인원수에 따른 별도 라벨 없음 | `{P}정지 상태를 유지해라.` |
| `resume` | 양보 후 주행 재개 | 연속 자차 속도·궤적, 보행자 기록 | 양보가 해소되어 출발 또는 정상 진행으로 전환한 최초 프레임 | `{S}주행을 재개해라.` |
| `normal` | 별도 보행자 대응 없음 | 자차·보행자·판정된 이벤트 | 관련 대응이 없거나 재개 이벤트 이후 | `{S}주행을 이어가라.` |
| `unknown` | 행동 판정 불가 | GT 유효성·자차·보행자 기록 | 다른 원인의 감속·정지와 구별 불가 또는 필요한 기록 불충분 | 유효한 상황만 생성. 행동 supervision 제외 |

- `{P}`는 현재 유효한 대응 보행자 N명의 상황 문장과 뒤의 공백이다. 1명이면 `자차 {위치}에 보행자가 있다.`; 여러 명이면 `자차 {위치1}에 보행자 1명, {위치2}에 보행자 1명, …이 있다.`로 확장한다. 행동 문장은 한 번 붙이고 객체 목록을 두 명에서 자르지 않는다.
- `approach`도 단일 위치 예시로 제한하지 않는다. 현재 위치에 맞춘 `{P}현재 주행을 유지해라.`를 사용한다. `resume`·`normal`의 `{S}`에도 유효한 다중 보행자 상황을 사용할 수 있다.
- 정적 장애물의 `avoiding`은 보행자 표에 넣지 않는다. 보행자는 실제 양보 행동에 따라 `yielding` 또는 `waiting` 등을 유지한다. 두 Zone 모두 설명 대상 변경과 행동 단계 전환을 구분한다.
- 아직 등장하지 않은 보행자의 위치나 예정 횡단 순서를 문장에 넣지 않는다.
- 계속 정지한 상태에서 대상만 바뀌면 `waiting`, 이동하며 양보를 이어가면 `yielding` 유지. 기존 양보가 해소된 후 다시 양보를 시작한 경우에 새 `yield_start` 부여.
- 양보하면서 계속 이동한 사례는 `waiting`을 거칠 필요가 없다.
- 미검출만으로 양보 해소·재개를 판정하지 않는다.
- 현재 runner는 보행자 녹색 신호 확인을 횡단 조건으로 사용하지 않는다. 자차 속도·도착시간·정지거리 조건으로 횡단을 트리거하되 차량 진행 신호를 검사한다. 일부 횡단 위치에서는 `pre_signal_guard`로 차량 직진 녹색을 요청·검증하며, 다른 위치에서도 차량 적색/대기 시 새 횡단을 보류한다. 차량 신호에 따른 정지를 보행자 양보로 오인하지 않는다. 이는 현재 코드의 제어 계약이며 모든 과거 수집 run의 실제 신호 상태를 증명하지 않는다.

## 7. 회전교차로

| 라벨 | 의미 | 근거 데이터 | 개념적 판정 조건 | Instruction 틀 |
|---|---|---|---|---|
| `approach` | 진입 전 접근 | 자차 위치·속도·궤적, 구간, 차량 GT | 진입 전이고 양보·합류 시작 전 | `{S}회전교차로 진입 지점으로 진행해라.` |
| `yield_start` | 진입 차량 흐름에 양보 시작 | 자차·차량 위치·속도·궤적 | 주변 차량에 대응한 양보 시작 최초 프레임 | `{S}해당 차량에 양보해라.` |
| `yielding` | 이동 중 진입 양보 | 자차·차량 기록, 양보 이벤트 | 양보 시작 이후이며 이동하면서 이어감 | `{S}해당 차량에 양보해라.` |
| `waiting` | 정지하며 진입 대기 | 자차 속도·주변 차량 기록 | 주변 차량에 양보하며 진입 전 정지 | `{S}정지 상태를 유지해라.` |
| `merge_start` | 합류 시작 | 자차 궤적·heading, 구간·기준 경로, 차량 기록 | 회전교차로 흐름에 합류하는 움직임의 최초 프레임 | `{S}회전교차로에 합류해라.` |
| `merging` | 합류 진행 | 자차·주변 차량 기록, 합류 이벤트 | 합류 시작 이후 완료 전 | `{S}회전교차로에 합류해라.` |
| `following` | 앞차 추종 | 자차·앞차의 연속 위치·속도·궤적 | 앞차를 대상으로 속도·간격을 조절하며 주행 | `자차 앞쪽에 차량이 있다. 앞차를 따라 주행해라.` |
| `follow_decelerating` | 앞차 대응 일반 감속 | 자차·앞차 속도·위치 | 앞차 감속·간격 감소에 대응한 일반 감속 | `자차 앞쪽에 차량이 있다. 감속해라.` |
| `emergency_braking` | 앞차 급감속 대응 급제동 | 자차·앞차 속도·위치·궤적 | 앞차 급감속·급정거에 expert도 급제동 | `자차 앞쪽에 차량이 있다. 즉시 강하게 제동해라.` |
| `following_stopped` | 앞차 뒤 정지 유지 | 자차·앞차 속도·위치, 직전 행동 | 앞차 대응 제동 후 정지 유지 | `자차 앞쪽에 차량이 있다. 정지 상태를 유지해라.` |
| `resume` | 앞차 추종 재개 | 자차·앞차 속도·궤적 | 앞차 대기·감속 이후 추종 재개 최초 프레임 | `자차 앞쪽에 차량이 있다. 앞차를 따라 주행을 재개해라.` |
| `normal` | 별도 차량 대응 없음 | 자차·차량·구간 기록 | 양보·합류·추종 등 별도 대응 없음 | `{S}주행을 이어가라.` |
| `unknown` | 행동 판정 불가 | GT 유효성·주행 기록 | 원인·대상·행동 종류를 구별하기 어려움 | 유효한 상황만 생성. 행동 supervision 제외 |

- 진입 대기 후 합류하며 출발하면 `merge_start`. 앞차 대기 후 추종 재개인 `resume`와 구별한다.
- 실제 합류 간격을 이루는 두 차량을 확인한 경우: `자차 {위치1}에 차량 1대, {위치2}에 다른 차량 1대가 있다. 두 차량 사이로 합류해라.`
- 합류 완료 후 실제 상태에 따라 `following` 또는 `normal`로 전환한다. 별도 합류 완료 문장은 현재 명세에 없다.

## 8. 고속도로

| 라벨 | 의미 | 근거 데이터 | 개념적 판정 조건 | Instruction 틀 |
|---|---|---|---|---|
| `approach` | 관련 차량·장애물 접근 | 자차·객체 위치·속도·궤적 | 접근 중이며 아직 추종 조정·양보·차로 변경 전 | `{S}현재 주행을 유지해라.` |

| `follow_decelerating` | 앞차 대응 일반 감속 | 자차·앞차 속도·위치 | 앞차 감속·간격 감소에 대응한 일반 감속 | `자차 앞쪽에 차량이 있다. 감속해라.` |
| `emergency_braking` | 앞차 급감속 대응 급제동 | 자차·앞차 속도·위치·궤적 | 앞차 급감속·급정거에 expert도 급제동 | `자차 앞쪽에 차량이 있다. 즉시 강하게 제동해라.` |
| `following_stopped` | 앞차 뒤 정지 유지 | 자차·앞차 속도·위치, 직전 행동 | 앞차 대응 제동 후 정지 유지 | `자차 앞쪽에 차량이 있다. 정지 상태를 유지해라.` |
| `resume` | 앞차 추종 재개 | 자차·앞차 속도·궤적 | 앞차 대기·감속 이후 추종 재개 최초 프레임 | `자차 앞쪽에 차량이 있다. 앞차를 따라 주행을 재개해라.` |
| `lane_change_start` | 좌우 차로 변경 시작 | 자차 궤적·heading, 경로·차로 정보, 객체 기록 | 목표 차로로 이동이 시작된 최초 프레임 | `{S}{방향} 차로로 이동해라.` |
| `lane_changing` | 좌우 차로 변경 진행 | 자차·경로·차로 정보, 변경 이벤트 | 변경 시작 이후 목표 차로 정렬 완료 전 | `{S}{방향} 차로로 이동해라.` |
| `lane_change_completed` | 차로 변경 완료 이벤트 | 자차 위치·heading, 경로·차로 정보 | 목표 차로 진입·정렬이 완료된 최초 프레임 | `{S}현재 차로를 따라 주행해라.` |
| `yielding` | 끼어드는 차량에 양보 | 자차·주변 차량 위치·속도·궤적 | 다른 차량 진입에 대응한 expert 양보 행동 | `{S}해당 차량에 양보해라.` |
| `normal` | 별도 객체 대응 없음 | 자차·객체·행동 기록 | 추종·양보·차로 변경 등 별도 대응 없음 | `{S}주행을 이어가라.` |
| `unknown` | 행동 판정 불가 | GT 유효성·주행 기록 | 행동 종류·대상 구별 불가 또는 기록 불충분 | 유효한 상황만 생성. 행동 supervision 제외 |

- 차로 내 회피는 정적 장애물의 `avoid_start`·`avoiding` 의미를 재사용한다. 단순 횡이동을 차로 변경이라고 부르지 않는다.
- 고속도로 `yielding`은 시작·진행을 별도 문장/라벨로 나누지 않은 상태다. 라벨 이름의 공통 의미는 양보 수행이며, 실제 이동·정지 상태도 내부 기록에 보존한다. 정지했다면 “해당 차량에 양보해라”보다 정지 유지 문장을 사용하도록 사건 확장을 검토한다.
- 고속도로 진입 합류·이탈은 현재 표에서 확정하지 않았다. 실제 수집 시나리오 범위를 확인한 후 추가할 사용자 검토 항목이다.

## 9. 터널

현재 full-loop 설정에는 앞차 급제동·정지 유지·재출발 이벤트가 있다. 이벤트 생성 거리·시간은 라벨 판정 임계값으로 재사용하지 않는다.

|---|---|---|---|---|
| `approach` | 앞차 접근 | 자차·앞차 위치·속도·궤적 | 접근 중이며 추종 조정·제동 대응 전 | `자차 앞쪽에 차량이 있다. 현재 주행을 유지해라.` |
| `following` | 앞차 추종 | 자차·앞차 위치·속도·궤적 | 앞차를 대상으로 속도·간격을 조절하며 주행 | `자차 앞쪽에 차량이 있다. 앞차를 따라 주행해라.` |
| `follow_decelerating` | 앞차 대응 일반 감속 | 자차·앞차 속도·위치 | 앞차 감속·간격 감소에 대응한 일반 감속 | `자차 앞쪽에 차량이 있다. 감속해라.` |
| `emergency_braking` | 앞차 급감속 대응 급제동 | 자차·앞차 속도·위치·궤적 | 앞차 급감속·급정거에 expert도 급제동 | `자차 앞쪽에 차량이 있다. 즉시 강하게 제동해라.` |
| `following_stopped` | 앞차 뒤 정지 유지 | 자차·앞차 속도·위치, 직전 행동 | 앞차 대응 제동 후 정지 유지 | `자차 앞쪽에 차량이 있다. 정지 상태를 유지해라.` |
| `resume` | 앞차 추종 재개 | 자차·앞차 속도·궤적 | 대기·감속 후 추종 재개 최초 프레임 | `자차 앞쪽에 차량이 있다. 앞차를 따라 주행을 재개해라.` |
| `normal` | 별도 차량 대응 없음 | 자차·차량·행동 기록 | 별도 추종·제동 대응 없음 | `{S}주행을 이어가라.` |
| `unknown` | 행동 판정 불가 | GT 유효성·주행 기록 | 대응 원인·행동 종류 불명확 또는 기록 불충분 | 유효한 상황만 생성. 행동 supervision 제외 |

- 앞차가 급제동했더라도 자차가 일반 감속했다면 `follow_decelerating`이다.
- 앞차가 출발해도 자차가 정지 상태면 `following_stopped` 유지. 자차가 재개한 최초 프레임에만 `resume` 부여.
- 감속만 하고 주행을 이어갔다면 정지 상태를 거칠 필요가 없다.
- 터널이라는 이유만으로 GPS 이상, 차로 변경, 장애물 회피를 추가하지 않는다.

## 10. 다중 객체·상태 겹침·예외 처리

### 10.1 대상 선택과 나열

- 현재 행동에 관련된 유효 객체만 선택한다. 전체 GT inventory를 모두 문장에 나열하지 않는다.
- 개체 추적 ID와 이벤트 ID는 문장상의 첫째/둘째 순번과 분리한다.
- 이번 통합본의 제안: 문장 순서는 이벤트에서 정한 주 대상, 보조 대상 순으로 고정하고 거리 변화만으로 매 프레임 재정렬하지 않는다. 좌·우 한 쌍의 통과 문장은 왼쪽 객체를 먼저 적는다. 동순위 결정 방식은 구현 설정에 남긴다.
- 한 객체를 통과하면 남은 대상 중심으로 상황을 갱신한다. 정적 회피의 방향 문장은 현재 경로 구간을 따르며 전체 이벤트 내에서도 바뀔 수 있다.
- 여러 객체를 한 동작으로 통과했다면 존재하지 않는 새 시작 이벤트를 생성하지 않는다.
- 보행자는 인원수 상한 없이 현재 유효한 대응 대상을 설명한다. 모델 길이 제한을 넘으면 조용히 일부를 자르지 말고 초과 사례를 기록한다. 그 외 세 개 이상 객체의 문장 길이·대상 상한은 아직 미정이다.

### 10.2 우선순위와 의미 일관성

- 내부 행동 상태는 여러 개가 동시에 존재할 수 있다. 예: 합류 진행 중 급제동.
- 최종 문장은 실제 급제동, 정지 유지처럼 즉각적인 동작을 합류·회피 지시보다 우선한다. 내부의 합류·회피 이벤트를 지우지는 않는다.
- 동시에 성립하는 양보·감속 등의 세부 충돌 규칙은 원인과 대상이 확인된 행동을 우선하도록 구현하고 테스트한다. 새로운 조합 문장을 임의 생성하지 않는다.
- `approach`는 식별된 대응 사건의 시작 전, `normal`은 현재 관련 대응 사건이 없는 상태다. 단순히 객체가 보인다는 이유로 `approach`를 붙이지 않는다.
- `waiting`은 보행자/진입 양보 정지, `following_stopped`는 앞차 추종 중 정지다. 출력 문장은 같아도 원인 라벨은 보존한다.
- `avoid_start`/`avoiding`, `yield_start`/`yielding`, `merge_start`/`merging`, `lane_change_start`/`lane_changing`은 같은 문장을 허용한다. 문장 loss만으로 단계 차이를 별도 감독한다고 주장하지 않는다.
- `resume`은 최초 재개 프레임 이벤트이고 이후 실제 상태에 따라 추종·정상 등으로 전환한다.
- `completed`, `lane_change_completed`는 완료 첫 프레임 이벤트다. 완료 문장을 계속 반복하지 않는다.

### 10.3 유효성

상황 유효성과 행동 유효성을 독립적으로 기록한다.

| 상황 | 행동 | 처리 |
|---|---|---|
| 유효 | 유효 | 상황+행동 문장 |
| 유효 | 불확실 | 상황만 supervision. 행동 마스크 false |
| 관련 객체 없음이 확인됨 | 유효 | 객체 존재 문장 없이 행동 문장 |
| 객체 GT 누락/불확실 | 독립 근거로 유효 | 유효한 행동만 사용 가능. 이를 객체 부재로 해석하지 않음 |
| 불확실 | 불확실 | 해당 Situation supervision 제외 |

- `unknown`은 행동 불확실성을 나타내며 정상 주행 정답으로 대체하지 않는다.
- 미검출만으로 통과·양보 해소·회피 완료를 판정하지 않는다.
- “해당 차량”, “두 장애물”처럼 대상 지시가 필요한 문장은 유효 대상을 설명할 수 없을 때 그대로 발행하지 않는다.
- 문장 일부만 유효한 경우 의미를 보존하는 loss mask가 필요하다. 단순히 행동 문장을 삭제하고 전체 문장 종료를 학습시키는 것이 행동 loss 제외와 같지는 않다. 부분 감독을 지원하지 않는 구현은 해당 샘플의 Situation loss를 제외한다.

## 11. 프레임 라벨과 학습 window

### 11.1 Instruction 생성 순서 — 오른쪽 회피 예시

**이미 연결된 프레임별 데이터를 읽어, 각 프레임에 상황 문장과 행동 문장을 작성한다.** 아래의 프레임 번호·좌표·거리는 설명용 예시이며 실제 수집 결과나 판정 임계값이 아니다.

**1단계. 연속된 expert 주행 기록에서 각 프레임의 행동을 판정한다.**

프레임 100, 101, 102의 자차 위치·방향·속도와 앞뒤 주행 기록을 확인한다. 판정 결과가 다음과 같다고 가정한다.

| 프레임 | expert 행동 판정 | 내부 라벨 |
|---|---|---|
| 100 | 아직 회피하지 않고 주행 중 | `approach` |
| 101 | 오른쪽 회피가 시작됨 | `avoid_start` |
| 102 | 오른쪽 회피가 이어짐 | `avoiding` |

여기서 “회피 시작 프레임을 찾는다”는 말은 **연속 주행 기록 중 회피 시작으로 판정된 데이터의 `frame_id`를 정한다**는 뜻이다. 예시에서는 101이다. 장애물까지 14m인 프레임을 먼저 검색하는 것이 아니다. 행동 검출 방식은 구현 담당자가 데이터로 검증한다.

**2단계. 그 회피가 어떤 장애물에 대한 행동인지 정한다.**

예시에서는 회피 대상이 `obstacle_1`이라고 가정한다. 객체 ID를 보존해 프레임이 바뀌어도 같은 장애물을 추적한다. 여러 객체 중 단순히 가장 가까운 객체를 매번 새 대상으로 선택하지 않는다.

**3단계. 프레임 101에 연결된 자차 위치와 대상 장애물 위치를 읽는다.**

| 읽을 데이터 | 설명용 값 |
|---|---|
| 프레임 101의 자차 GT 위치 | `(x=100m, y=50m)` |
| 프레임 101의 `obstacle_1` GT 위치 | `(x=114m, y=50m)` |
| 프레임 101의 자차 방향 | 월드 좌표의 +x 방향을 바라봄 |

객체 좌표는 4.1절에서 정한 GT 위치 출처를 사용한다. 다른 프레임의 위치나 미래 waypoint 위치를 가져오지 않는다.

**4단계. 자차 기준 방향을 구하고, 내부 검수용 거리를 계산한다.**

위 예시에서 두 위치의 수평 직선거리는 다음과 같다.

```text
거리 = sqrt((114 - 100)^2 + (50 - 50)^2) = 14m
자차가 +x를 바라보므로 장애물의 상대 위치 = 앞쪽
```

**거리 수치는 내부 판정·검수 데이터이며 문장에는 넣지 않는다.** 예시의 14m나 실제 계산값 14.2m는 내부 데이터로 보존할 수 있다. 회피 시작의 고정 임계값이나 이동 거리 지시가 아니다.

거리와 방향은 따로 계산한다. 두 점의 거리만으로는 앞쪽·오른쪽 앞을 구별할 수 없으므로 위치 표현에는 자차 yaw도 사용한다.

**5단계. 상황 문장과 행동 문장을 합쳐 프레임 101의 라벨로 저장한다.**

```text
상황: 자차 앞쪽에 정적 장애물이 있다.
행동: 오른쪽으로 회피해라.

최종 instruction:
자차 앞쪽에 정적 장애물이 있다. 오른쪽으로 회피해라.

저장 대상: 해당 episode의 frame_id = 101
내부 행동 라벨: avoid_start
대상 객체 ID: obstacle_1
```

최종 표현 depth에 따라 `avoid_start`와 `avoiding`은 둘 다 “오른쪽으로 회피해라”를 사용한다. 시작·진행의 차이는 내부 라벨로 보존한다.

**6단계. 회피 시작 프레임뿐 아니라 다른 프레임에도 같은 절차를 적용한다.**

| 프레임 | 해당 프레임에서 계산한 상황 | 해당 프레임의 행동 | 최종 instruction 예시 |
|---|---|---|---|
| 100 | 대상이 앞쪽 | 회피 전 주행 유지 | 자차 앞쪽에 정적 장애물이 있다. 현재 주행을 유지해라. |
| 101 | 대상이 앞쪽 | 오른쪽 회피 시작 | 자차 앞쪽에 정적 장애물이 있다. 오른쪽으로 회피해라. |
| 102 | 대상이 왼쪽 앞 | 오른쪽 회피 진행 | 자차 왼쪽 앞에 정적 장애물이 있다. 오른쪽으로 회피해라. |

객체 위치와 내부 거리 데이터는 해당 프레임의 GT로 갱신한다. 다른 주행에서 대상까지 남은 거리가 달라도 문장에 거리 수치를 넣지 않는다. 현재 위치와 expert 행동이 같으면 같은 instruction을 사용할 수 있다.

> 생성 순서: **프레임별 expert 행동 판정 → 행동 대상 객체 선택 → 같은 프레임의 자차 pose·객체 좌표로 상대 위치 계산 → 거리 수치 없이 상황·행동 문장 결합 → 해당 frame_id에 저장.**

### 11.2 생성한 라벨을 학습에 사용하는 규칙

1. 개별 프레임에 라벨을 생성한다. 시작 프레임만 저장하는 방식이 아니다.
2. 시작·진행·종료 판정은 연속 expert 기록을 사용할 수 있다. 미래 궤적은 오프라인 정답 판정 근거이며 모델 입력으로 노출하지 않는다.
3. 상황의 위치·객체 존재와 내부 거리 데이터는 반드시 그 프레임의 GT를 사용한다. 거리 수치는 문장에 넣지 않는다. 미래에 등장할 객체를 현재 상황에 넣지 않는다.
4. 학습 window 예: `[t-20, t-18, ..., t-2, t]`. Situation Head의 정답은 `t` 프레임 라벨이다.
5. 과거 10개 프레임은 시각 문맥이다. 현재 상황 문장을 과거 프레임의 상황 정답으로 복제하지 않는다.
6. 시작 이벤트가 중요하다면 window anchor 샘플링으로 보존할 수 있다. 시작 프레임이 과거 슬롯에 들어갔다는 것만으로 onset이 직접 감독되는 것은 아니다.
7. 궤적 loss를 현재 프레임에만 적용할지, 각 시점별 유효 입력으로 모든 프레임에 적용할지는 별도 모델 설계 사항이다. 보조 Situation loss의 마지막 프레임 규칙과 혼동하지 않는다.
8. episode 경계·시간 단절·Zone 전환에서의 window 허용 범위는 구현 설정에 명시한다. 현재 라벨의 Zone 기준은 anchor 프레임이다.

## 12. 제안 저장 형식

다음은 신규 sidecar 예시이며 기존 collector 스키마를 변경한 결과가 아니다. 원본 GT·manifest는 보존한다.

```json
{
  "schema_version": "situation-instruction-label-v1",
  "episode_id": "example_episode",
  "frame_id": 101,
  "sensor_time_ns": 10100000000,
  "zone": "static_obstacle",
  "event_id": "avoidance_01",
  "label": "avoid_start",
  "situation": {
    "valid": true,
    "objects": [
      {
        "instance_key": "obstacle_1",
        "object_type": "static_obstacle",
        "relative_position": "front",
        "distance_m": 14.2,
        "position_source": "recorded_object_gt_original_position"
      }
    ],
    "text": "자차 앞쪽에 정적 장애물이 있다."
  },
  "action": {
    "valid": true,
    "purpose": "avoidance",
    "phase": "start",
    "direction": "right",
    "text": "오른쪽으로 회피해라."
  },
  "instruction": "자차 앞쪽에 정적 장애물이 있다. 오른쪽으로 회피해라.",
  "rule_version": "implementation-defined",
  "evidence_refs": []
}
```

- `objects`는 항상 목록으로 두어 단일·다중 객체를 같은 구조로 처리한다.
- `distance_m`은 내부 판정·검수용 메타데이터이며 `situation.text`와 `instruction`에는 포함하지 않는다.
- `label`은 Zone과 함께 해석한다. 원인/대상/단계는 구조화 필드에도 보존한다.
- `evidence_refs`에 원본 프레임·객체·분석 기록 참조를 남긴다. 예시의 빈 목록은 완성된 판정 증거를 뜻하지 않는다.
- 속도 상태·신뢰도·판정 실패 사유 등 검수 메타데이터는 확장할 수 있다. 추가 메타데이터가 문장 depth 확장을 의미하지 않는다.

## 13. 통합 점검 결과와 미확정 사항

### 정리한 중복·용어

- 라벨 정의표와 위치별 예시를 같은 의미 체계로 통합했다. 좌우 위치별로 새 행동 라벨을 만들지 않는다.
- 회전교차로·고속도로·터널의 추종/감속/급제동/정지/재개 의미와 문장을 통일했다.
- 시작·진행 라벨의 동일 문장을 허용하고 단계 supervision의 한계를 명시했다.
- 다중 객체는 별도 행동이 아니라 객체 목록과 문장 확장으로 처리했다.
- 완료/재개 이벤트와 지속 상태를 구별했다.
- 조건부 `{S}`가 관련 객체 없음과 GT 누락을 혼동하지 않도록 유효성 처리를 명시했다.
- “expert 행동 연결”에서 실제 궤적 GT와 raw 조향 명령의 차이를 명시했다.

### 구현 담당자 결정·검증 항목

- 실제 회피 시작·복귀, 양보 원인, 추종, 합류·차로 변경, 일반 감속·급제동을 판정하는 알고리즘.
- 각 알고리즘의 수치 임계값·필터·지속 확인 시간·경계 프레임 처리. 과거 제안된 0.15m/s, 0.3초, 0.20m, 3°, 0.5초는 채택하지 않았다.
- 시작 정의가 계획 결정/제어 명령/관측 움직임 중 무엇인지 증거에 맞춰 명시. 이용할 수 없는 내부 결정 순간을 추정치 없이 확정하지 않는다.
- 위치 영역 경계, Zone별 대상 선택, 동순위 객체 순서, window anchor 선택.
- 각 원본의 좌표·위치 기준점·시각 유효성을 검사하고 provenance 보존.
- 부분 supervision, 공유 특징 gradient, 추론에서 Head 제거 후 입력 일관성 검증.
- 옛 도식의 Situation Head→LLM `F_s` 연결은 합의한 보조 Head 구조에 맞춰 제거하고 모델 명세를 갱신한다. Zone·Navigation 정보의 최종 추론 가용성은 별도 입력 계약과 대조한다.
- 데이터 확인 후 적용 가능한 행동만 발행한다. 목록에 있다는 이유로 이벤트를 만들어내지 않는다.

### 사용자 의미 확인이 필요한 잔여 항목

1. 정적 장애물 대응 중 실제 감속·정지를 문장에 따로 표현할지, 회피 문장과 충돌하는 프레임은 행동 supervision에서 제외할지.
2. 고속도로에서 끼어드는 차량에 양보하며 완전히 정지한 사례의 라벨 확장. 현재 `yielding` 문장만으로 정지 상태를 구체적으로 표현하지 않는다.
3. 고속도로 진입 합류·이탈이 실제 라벨링 범위에 포함되는지.
4. 보행자 이외의 관련 객체가 세 개 이상일 때 모두 기술할지, 일부 선택할지와 문장 길이 정책. 보행자 인원수 제한은 두지 않는 것으로 확정.

이 항목을 임의로 확정된 규칙처럼 처리하지 않는다. 기존 다섯 Zone의 명세로 처리할 수 있는 사례의 구현은 별도로 진행할 수 있다.

## 14. 인수 확인 항목

- 모든 라벨이 Zone·대상·프레임·원본 근거로 추적되는가?
- 문장 속 객체 종류·위치가 해당 프레임 GT와 일치하며 거리 수치가 제외되어 있는가?
- 일반 커브/속도 조정을 장애물 회피·양보로 잘못 분류하지 않는가?
- 앞차 급정거 여부와 자차 실제 급제동 여부를 구분했는가?
- 대상 변경·순차 등장·반대 조향 때문에 새 시작 이벤트가 불필요하게 생기지 않는가?
- GT 누락이 정상/완료/재개 라벨로 바뀌지 않는가?
- 문장에 미래 등장 정보·목표 속도·행동 이유가 추가되지 않는가?
- Situation GT는 보조 정답으로만 쓰이고 추론에서 제거될 출력을 LLM이 필수로 요구하지 않는가?
- 자동 판정 규칙과 검수 결과는 버전으로 남겼는가?
