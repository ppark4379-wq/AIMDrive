# Waypoint 제어기 수정 및 실험 — 2026-09-22

## 결론과 검증 범위

**시간으로 waypoint를 버리던 처리, 방향 오차만 이용한 조향, 초과속도에서 일괄 최대 제동하는 처리를 수정했다.** 기본 제어기는 차량 제원 기반 Pure Pursuit와 MoraiDrive expert 방식 종방향 PID다.

실제 과거 주행 기록 재생, 가상 차량 폐루프 계산, 자동 회귀 테스트 90개, headless Edge 화면 동작 검증을 마쳤다. **이번 수정으로 실제 MORAI 차량을 주행시킨 결과는 없다.** 시작점/센서 송신 준비 여부는 확인되지 않았다. 따라서 아래 가상 차량 오차를 실제 MORAI 개선 수치로 해석하면 안 된다.

신경망 체크포인트, Gumbel 선택, navigation 생성 조건은 이번 제어기 수정 대상이 아니다. 기존 93epoch best 모델과 30m 안내 설정, 목표 속도 상한 1m/s를 사용한다.

## 1. 기존 제어기 문제와 변경

| 항목 | 이전 | 변경 후 |
|---|---|---|
| 경로 점 선택 | 예측 horizon이 지나면 삭제 | 현재 위치에서 경로에 투영한 이후의 전방 점 사용 |
| 저속과 예측 속도 차이 | 앞의 점이 남아 있어도 더 먼 두 점 선택 | 실제 속도 기준 목표 거리, 선분 위 보간 |
| 조향 | 목표 방향/90°를 창 평균 PID에 입력 | 실제 거리·곡률·휠베이스 → 휠 각도 |
| 차량 제원 | 조향에 3m/40°가 직접 반영되지 않음 | wheelbase=3m, wheel angle=40° 반영 |
| 속도 | LMDrive의 창 평균/차분 PID | expert의 dt 기반 적분/미분 PID |
| 초과 속도 | 목표×1.1 초과 시 brake=1 | 속도 오차 및 PID 상태에 따라 가속/제동량 계산 |
| 화면 | 예측 경로와 정규화 steer 중심 | 실제 제어 목표점, 요청/수신 휠각, 계산 frame 추가 |

예측 유효시간 1.25초는 유지했다. 새 예측이 수신되더라도 이전 명령의 유효시간이 늘어나지 않으며, 만료 시 다음 정규 tick 전이라도 최신 예측으로 재계산한다. 센서 만료·위치 점프·시간 역행·이력 초기화·전방 경로 부재의 제동 처리를 유지했다.

## 2. 조향 계산과 제원 해석

모델 좌표는 `[left, -forward]`. 추론 당시 차량 pose에서 현재 pose로 변환해 `[left, forward]` 경로를 얻는다. 예측 당시 원점과 5개 예측 점을 연결하고, 현재 위치에서 가까운 경로 선분에 투영한 다음 진행 순서대로 목표점을 찾는다. 예측 원점은 추가 신경망 출력이 아니라 첫 점까지의 연결 시작점이다.

```text
L = clip(0.65 × actual_speed_mps, 2.0, 30.0)
curvature = 2 × aim_left / (aim_left² + aim_forward²)
wheel_angle = atan(3.0 × curvature)
UDP steer = clip(wheel_angle_deg, -40, 40) / 40 × steering_sign
```

목표 거리 원과 선분의 교차점을 보간하므로 waypoint 간격이 커도 불필요하게 먼 점으로 건너뛰지 않는다. 경로가 목표 거리보다 짧으면 마지막 전방 점을 쓰되 실제 거리를 분모로 계산한다.

임의의 0.8 조향 감쇠나 추가 rate limit을 넣지 않았다. ±1은 UDP 입력 범위, ±40°는 제공받은 휠 각도다. 최소 회전 반경 5.87m는 차체 외곽/바퀴/후륜 중심 중 측정 기준이 명시되지 않아 추가 clamp로 사용하지 않았다. 차체 length=4.635, width=1.892, height=2.434, front overhang=.845, rear overhang=.79는 config에 보존한다.

**남은 기준점 확인:** `reference_to_rear_axle_m=0`은 expert와 동일하게 현재 pose를 기준으로 계산하는 초기 가정이다. 실제 GPS/모델 좌표 원점이 후륜보다 앞에 있으면 그 거리를 설정해야 한다. 입력 제원만으로 센서 원점을 확정할 수 없어 임의로 차량 중심이라고 가정해 이동시키지 않았다. 이 값은 실제 폐루프 오차에 영향을 줄 수 있다.

[MORAI 공식 UDP 문서](https://help-morai-sim.scrollhelp.site/ko/morai-sim-drive/24.R1.0/ros-1)의 EgoCtrlCmd 송신 steer는 정규화 값, EgoVehicleStatus steer는 degree로 설명되어 있다. Expert ROS 제어 경로의 rad 값을 UDP에 그대로 적용하지 않았다. 실제 설치 환경의 양수 좌회전 부호는 이전 기록 검증을 유지했다.

## 4. 가상 차량의 횡방향 폐루프 실험

신경망 대신 이상적인 원형 기준 경로 위의 0.5/1/1.5/2/2.5초 waypoint를 사용했다. 예측 속도 4.3m/s, 실제 차량 속도 1m/s, 예측 5Hz, 지연 0.75초, 제어 10Hz, 60초간 비교했다. 휠베이스 3m bicycle 모델이며, 시험용 조향 응답 시정수 0.2초와 속도 60°/s를 가정했다. **이 응답 제한은 가상 차량에만 있고 실제 제어기에는 추가하지 않았다.** 오차는 기준 원에서의 반경 방향 절대 편차다.

## 5. 종방향 PID 비교와 선택

참고 원본:

- `MoraiDrive/expert/src/expert/src/control/pid.py`: dt 적분/미분, derivative-on-measurement 옵션, anti-windup.
- `MoraiDrive/expert/src/expert/src/autonomous_driving.py`: m/s 목표/실제 속도 전달, 정지 시 reset.
- Expert 기본 P/I/D = **.075 / .0001 / .025**.

새 구현은 실제 dt와 출력 포화에 맞춘 적분 억제를 사용한다. 양수 출력은 throttle, 음수 출력은 brake다. 목표 속도 변화에 의한 미분 제동 충격을 줄이기 위해 측정 속도 미분을 사용한다. 목표 ≤.05m/s이면 적분 초기화 및 최대 정지 제동한다.

가상 종방향 plant는 `dv/dt = 3×throttle - 5×brake - drag×v - resistance`이고, 속도 음수는 0으로 처리했다. dt=.1초, 40초간 목표 1m/s 후 20초간 목표 0. 마지막 정상 구간 30~40초 평균을 비교했다. 실제 MORAI 엔진/변속기/브레이크 모델을 식별한 결과는 아니다.

| P / I (D=.025 고정) | drag=.05, 저항=.05 평균 속도 | drag=.1, 저항=.1 평균 속도 | 저항 없음 최대 속도 |
|---|---:|---:|---:|
| .075 / .0001 (expert 원계수) | .6511m/s | .4036m/s | 1.0059m/s |
| .075 / .01 | 1.0078m/s | 1.0016m/s | 1.2385m/s |
| .15 / .02 | 1.0011m/s | .9992m/s | 1.1593m/s |
| **.15 / .01 (채택)** | **.9939m/s** | **.9628m/s** | **1.0993m/s** |
| .2 / .01 | .9852m/s | .9497m/s | 1.0642m/s |

원계수의 작은 I는 가정한 저항이 있을 때 정상 오차를 줄이는 속도가 느렸다. I만 .01로 올리면 저항 없는 조건의 overshoot가 컸다. P=.15와 I=.01을 저속 시험 시작점으로 선택했다. 가상 조건에서도 최대 약 10% overshoot가 있으므로 **완성된 최적 튜닝이라고 판단하지 않는다.**

새 PID의 `target=1, actual=1.12m/s, dt=.1`, 적분 초기 상태에서는 brake=.01812다. 기존의 brake=1보다 연속적인 제동을 만든다. 실제 차량이 속도 상한을 초과하지 않는다는 보장은 아니며 상한은 목표 속도에 적용된다.

## 6. 화면과 로그

- 주황색 원: 실제 제어 목표점.
- 파란 경로: 마지막 제어 계산 pose에서 본 변환된 전체 예측 경로.
- 요청 휠각 / 수신 휠각(degree), 실제 속도, 목표점 거리, 제어 frame, 최대 휠각 도달 여부.
- 카메라는 최신 예측 입력 frame이며, 제어 frame과 다르면 이를 읽을 수 있도록 표기.
- `control.jsonl`: 위 값, 실제 제어 pose/시각, 곡률, unclipped angle, PID의 P/I/D 항, prediction age 등을 저장.
- 제어 10Hz 사이 UDP 20Hz 유지 송신에서도 실제 사용한 frame/anchor를 보존한다. 새 prediction의 이름으로 옛 명령을 기록하지 않는다.

Headless Edge에서 가상 API 응답으로 목표점 마커, 요청 22.16°/수신 12.50°, 제어 frame 908/카메라 frame 909, 수신 휠각 누락 표기, stale 시 목표점 제거를 확인했다. JS 예외 없음. **UI 확인 숫자는 fixture 값이며 차량 계측값이 아니다.**

실제 주행에서는 요청/수신 휠각의 시차도 고려해야 한다. 요청은 충분한데 수신 응답이 지속적으로 작으면 차량 응답·단위·프로토콜을 확인하고, 수신 휠각은 잘 따라오지만 차량이 예측 경로를 벗어나면 기준점·목표 거리·지연을 확인한다.

## 8. 현재 설정과 실행

```text
controller = pure_pursuit
wheelbase = 3m; max wheel angle = 40°
lookahead = clip(.65 × actual speed, 2, 30)m
longitudinal P/I/D = .15 / .01 / .025
max target speed = 1m/s
control compute/send = 10Hz / 20Hz
```

기존 추론을 종료한 뒤 WSL `lmdrive` 환경의 VLDrive 폴더에서:

```bash
python inference/realtime_vldrive.py
```

현재 realtime config의 `control.enabled=true`이므로 별도 `--control.json` 인자가 필요 없다. 제한된 시간의 실주행 확인은 `--duration 45`를 추가하면 된다. 실제 MORAI 시작 위치·센서 송신 준비 후 확인해야 하며, 아직 실제 폐루프 개선 여부는 미검증이다. rollback은 `configs/vldrive_control.json`의 `controller`를 `lmdrive_pid`로 바꾼다.
