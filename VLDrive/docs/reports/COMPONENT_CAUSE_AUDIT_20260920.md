# VLDrive encoder / connector / LLM 독립 진단

실행일: 2026-09-20. 기존 모델·학습 설정·운영 추론 코드 변경 없이 완료. 실험용 코드·특징 파일·로그·예측기 가중치는 삭제 완료했으며, 이 Markdown 파일만 이번 실험의 최종 산출물로 남긴다.

## 판단

1. **직진의 횡방향 정보를 encoder가 전혀 제공하지 못한다는 설명은 지지되지 않는다.** 같은 검증 33개 장면에서 encoder waypoint 특징에 학습한 선형 예측기의 2.5초 좌우 MAE는 0.352m였다. 학습 GT를 섞은 대조군 0.719m, 학습 정답 평균만 출력하는 대조군 0.579m보다 작다.
2. **Connector가 그 정보를 전부 없앤다는 설명도 지지되지 않는다.** 토큰을 평균내지 않고 원래 index별로 유지한 connector 특징의 좌우 MAE는 0.433m였다. 토큰 평균을 쓴 경우 0.582m로 나빠져, pooling 방식 자체가 평가를 왜곡할 수 있음을 확인했다. 두 표현을 완전히 동일하다고 볼 수는 없어 pooling만의 인과효과를 확정하지 않는다.
3. **현재 최종 VLA의 좌우 출력은 이용 가능한 특징보다 부정확하다.** 같은 33개 검증 장면의 2.5초 좌우 MAE는 0.902m였다. 우선 조사할 구간은 Q-Former 출력 이후 언어 projection·LLM 처리·trajectory readout·학습 목표다. LLM 처리와 최종 head 중 하나만을 단일 원인으로 확정한 실험은 아니다.
4. 최종 waypoint head가 실제 받는 현재 frame의 LLM hidden state에 새 선형 예측기를 붙이면 좌우 MAE가 0.580m였다. 그러나 단순 평균 정답 대조군 0.579m와 사실상 같다. 따라서 이것만으로 LLM이 정확한 횡방향 정보를 보존했다거나 head 교체가 해결책이라고 결론 내리지 않는다.
5. **전후 위치까지 포함한 ADE에서는 기존 VLA(1.901m)가 모든 작은 예측기보다 좋았다.** 작은 예측기를 운영 모델 대신 쓰면 된다는 결과가 아니다. 횡방향 세부 정확도와 종방향 이동 거리 학습을 나누어 봐야 한다.
6. Encoder 자체 GRU head는 현재 시간 기반 GT와 크게 다르지만, checkpoint의 원래 `waypoint_target_policy=official_route_head_v1` 정의를 찾지 못했다. 이 head가 같은 시간 기반 목표로 학습됐다는 보장이 없어 **encoder 학습 실패 판정은 보류**한다. 앞선 진행 메시지의 큰 오차 설명은 이 한계를 반영해야 한다.

## Encoder 자체 head 평가와 조건의 한계

Checkpoint에 명시된 velocity_input, target_point_input 모두 constant_zero. 현재 캐시도 동일하다. 이전 답변에서 제시한 속도 입력 불일치 가능성은 이 checkpoint에 대해 근거가 없다.

반면 pretraining에는 `waypoint_target_policy=official_route_head_v1`가 저장되어 있다. 원래 학습 파일은 다른 환경의 `large_scale_3laps_02/.../training_dataset_v2_retry1`이며, 이번 basic_drive와 다르다. 원래 정책 구현·원본 manifest를 현 repository에서 찾지 못했다. sensor contract의 horizon 메타데이터만으로 policy의 실제 target 정의를 확정하지 않았다. 현 로컬 legacy labels.py도 당시 implementation hash와 달라 원래 정책의 증거로 사용하지 않았다.

진단값(동일 의미의 GT로 학습됐는지 미확인, 정상 성능 점수로 채택 금지):

|---|---:|---:|---:|
| Encoder GRU head | 10.723 | 13.466 | 1.063 |
| 기존 최종 VLA | 2.560 | 1.901 | 0.902 |

원본 센서 frame [20, 2427, 2983]에서도 encoder head를 직접 실행했다. cached token을 head에 넣은 결과와 최대 차이는 0.0001954m, token 최대 차이는 0.0011730. 모두 기존 atol=rtol=0.002 cache 비교 기준을 통과했다. 따라서 큰 전방 차이는 float16 캐시나 잘못 잘라낸 token 때문이라는 근거가 없다. Stage 1 출력 [right,-forward]를 Stage 2 [left,-forward]로 변환했다.

예: frame20의 2.5초 미래 전방 GT 24.655m, encoder GRU 2.283m, VLA 22.500m. 이 값만으로 encoder의 원래 학습 목표가 틀렸다고 단정할 수 없다. Encoder GRU 좌표는 운영 VLA 경로에 직접 전달되지 않는다.

## 작은 예측기 실험 방법

- 기존 encoder, CCDP/MEFA/Q-Former, LLM, 최종 head 모두 고정. 새 예측기만 CPU에서 학습했다.
- 각 경계 특징에 학습 자료만으로 feature별 표준화(std floor=0.001), PCA 32차원 및 whitening을 적용. PCA는 probe fit split만 사용하고 검증 GT는 보지 않았다.
- 내부 fit/dev: 시간 순 앞쪽 fit85, 뒤쪽 dev30, 경계 4.5초 purge로 5개 제외. 비선형 예측기는 fit85만 학습했다.
- 선형 ridge alpha 후보 0.001/0.01/0.1/1/10/100/1000을 내부 dev ADE로 선택, 이후 원래 train120으로 PCA·ridge를 다시 fit하여 val33 평가.
- 비선형 MLP: 32→64→ReLU→10, 2,762개 parameter. Adam lr0.003, weight_decay0.0001, full batch, 최대800 update. 학습 target을 fit mean/std(std floor0.1)로 표준화한 MSE 사용. 20 update마다 dev ADE 확인, 최저 dev checkpoint 선택. seed607/608/609 모두 평가. 운영 Stage 2의 L1 학습을 바꾼 것이 아니다.
- 숫자는 미터. ADE=5개 시간의 좌표 L2 평균, 좌우 MAE=좌우 절대오차 평균. PCA/MLP 용량·정규화로 인한 정보 손실 가능성이 있어 실패한 probe를 encoder/connector 정보 부재 증명으로 취급하지 않는다.
- Text는 작은 probe에 별도로 주지 않는다. LLM hidden에는 이미 text의 영향이 들어 있다. 직진 subset이며 일반 경로 지시 준수 성능을 비교한 실험이 아니다.

표현 정의:
- encoder_pool: 매 frame의 106 token 평균을 시간 순으로 연결.
- encoder_wp: 매 frame waypoint token 5개를 순서·시간 유지하여 연결.
- encoder_wp_current: 현재 frame의 waypoint token 5개만 사용.
- encoder_full_current: 현재 frame 106개 token을 index 유지하여 연결.
- connector_pool: 매 frame 유효 language token의 평균을 시간 순으로 연결.
- connector_unpooled_current: 현재 frame Q-Former hidden(768차원)을 원래 선택 token index 0~105에 배치, 미선택 위치 0. 토큰을 평균내지 않는다. language projection 이전 표현이므로 pooled 결과와 차이가 전부 pooling 때문이라고 단정하지 않는다.
- llm_readout: 실제 head에 들어가는 각 frame hidden 11개.
- llm_current: 실제 최종 좌표 head에 들어가는 현재 frame hidden 하나. head와 동일 입력을 다른 작은 예측기로 읽는 검사.

## Waypoint query의 실제 역할

Encoder decoder의 waypoint 특징은 token101~105(각256차원)다. Stage 1 GRU head는 이 특징을 좌표로 읽지만 Stage 2는 이 좌표 head를 건너뛰고 특징만 사용한다. Encoder query와 특징을 GT 좌표 자체로 해석하면 안 된다.

현재 connector는 선택된 특징을 Q-Former query로 사용하고 전체106개 특징을 temporal enhancement한 memory도 읽는다. waypoint token이 선택되지 않아도 그 정보가 memory에서 완전히 제거되는 것은 아니다. 이번 검증의 waypoint query 평균 선택 개수는 3.879/5, 하나도 선택되지 않은 anchor는 0/33이었다.

LLM의 기존 trajectory readout은 각 frame의 마지막 유효 visual token hidden을 사용한다(models/language_model.py:113 부근). 이 선택 방식과 최종 좌표 학습이 횡방향 정보를 얼마나 활용하는지는 다음 구분 대상이다. 마지막 token이라는 사실만으로 버그라 판정하지 않았다.

## 결론의 범위와 다음 단일 방향

원인이 하나의 모듈이라고 확정되지는 않았다. 다만 순서는 좁혀졌다: **encoder 전면 재학습이나 데이터 양 확대보다, Q-Former 출력 이후의 언어 projection과 횡방향 readout·trajectory 학습을 우선 조사한다.** Encoder waypoint 특징 및 connector 특징에 held-out 좌우 예측에 유용한 정보가 있다는 양성 결과가 있다. 최종 VLA가 종방향 ADE에서는 더 좋으므로 전체 모델을 작은 probe로 교체하지 않는다.

다음 통제 실험 후보는 동일 frozen connector·동일 instruction·동일 split을 유지하고 LLM의 전체 유효 visual hidden을 읽는 작은 head와 기존 last-token head를 비교하는 것이다. 새 readout은 반드시 학습 후 검증하며, 추론 때만 head를 바꾸는 식으로 판정하지 않는다. 별도로 encoder head의 원래 정확도를 판정하려면 official_route_head_v1 구현/원래 GT manifest가 필요하다. 이번 단계에서 이 추가 학습 또는 운영 모델 수정은 하지 않았다.

## 자원·정리
