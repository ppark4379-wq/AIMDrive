# VLDrive Stage 2 학습·readout 검증 — 2026-09-20

## 결론

**GT/프레임 연결 오류나 loss 합산 오류는 발견되지 않았다. 평균 토큰 readout 또는 head 단독 추가 학습이 현재 문제를 해결한다는 근거도 얻지 못했다. 반면, 학습 window가 허용하는 지시 이력과 실시간에서 사용하는 지시 이력의 차이는 코드와 데이터 양쪽에서 확인했다.** 이 차이를 다음 통제 실험의 우선 대상으로 삼는 것이 맞다. 첫 직진 구간의 모든 횡오차를 이 차이 하나로 설명하거나, LLM 자체가 정상이라고 확정하지 않는다.

이전 component 진단에서 'LLM 이후 readout을 우선 조사'하자는 가설을 이번에 시험했다. 단순 last→mean 교체로 개선되지 않아, last-token 선택 자체를 주원인이라고 단정할 수 없다.

## 1. 실제 학습 입력·GT·loss 연결

- 모델: outputs/logs/vldrive_20260919_182054_301289/model-best.pt, epoch 10, update 3730.
- 원래 train373 + val75 = 448개 window_indices 전부 검사. 창마다 11개 real frame, 총 4928개 supervision 항목(중복 frame 포함).
- 원본 sensor timeline의 현재 위치·heading과 0.5/1/1.5/2/2.5초 미래 위치를 사용하여 회전행렬로 GT를 독립 재계산. 기존 future_target 함수를 재사용하지 않았다. 최대 좌표 차이 0.0000019050m.
- 선택 frame 간격 0.2초에서 최대 차이 0.0초. frame index와 source timestamp 일치.
- epoch0 및 epoch14의 instruction sampling 896회 검사. 샘플링된 instruction instance가 해당 창 전체의 eligible 목록에 포함됨.
- 실제 model.loss와 직접 계산한 11프레임 전체 raw-coordinate L1 일치. 현재 NavigationCacheDataset은 frame_loss_mask를 반환하지 않아, loss는 모든 11개 프레임에 적용된다.
- 별도 auxiliary forward: pruning=0.002853167, reconstruction=0.162564769, cycle=0.191096440. `cycle - (10*pruning + reconstruction)`=0.0. 총 loss는 waypoint L1 + cycle.
- readout이 고르는 hidden을 실제 valid mask로 독립 재계산해 153개 창 ×11개 frame 모두 정확히 일치. padding 또는 다른 frame을 잘못 읽는 indexing 오류는 발견되지 않음.
- 참고 코드: datasets/navigation_cache_dataset.py:88 부근, models/vldrive.py:200 부근, models/language_model.py:113 부근, utils/trainer.py:489 부근. Dataset이 model_inputs와 training_targets를 분리하고, trainer가 epoch마다 set_epoch 및 loss.backward/optimizer.step을 호출함을 확인.

이것은 현 basic_drive의 Stage 2 연결 검사다. Stage 1 encoder의 원래 official_route_head_v1 target 정의나 카메라/LiDAR 물리적 동시성까지 검증했다는 뜻이 아니다.

## 2. 확인된 학습/실시간 지시 조건 차이

학습: NavigationLabels.eligible은 2초짜리 이력 전체에서 공통으로 적용되는 instruction instance를 요구한다. 없으면 학습 창으로 만들지 않거나 해당 instruction을 샘플링하지 않는다. 또한 복합/거리 지시의 첫 target이 이력 시작점보다 뒤에 있어야 한다.

실시간: live_pipeline은 마지막 anchor의 현재 instruction을 선택하여 기존 11프레임 전체와 함께 predict_window에 전달한다. instruction 변화만으로 history를 지우지는 않는다. NavigationEngine은 복합 지시를 두 번째 행동 종료까지 유지한다. 따라서 첫 번째 행동 이후에도 살아 있는 복합 지시가 학습 sampler에서는 제외될 수 있다.

녹화 경로의 모든 연속·유효 rolling history를 같은 코드로 조사했다. 11개 입력의 간격은 0.2초이고 가능한 마지막 anchor는 0.1초씩 이동하여 집계했다. 실제 UDP 로그에서 발생한 비율 또는 예측 실패율이 아니며, 서로 겹치는 window들이다.

| 정책 | 유효 history | 현재 active rule이 창 전체 학습 후보에 없음 | 이력 전체에 공통 아님 | 첫 target이 이력 시작 이전 | 어떤 공통 지시도 없음 |
|---|---:|---:|---:|---:|---:|
| 30m | 2618 | 875 | 558 | 317 | 339 |
| 20m | 2618 | 893 | 576 | 317 | 361 |

Instance ID 차이뿐 아니라 instruction_id(의미별 rule) 부재도 별도 집계했고 수치가 같았다. 20m 기준 893/2618=34.1%는 현재 active rule이 동일 이력의 학습 후보에 없다는 뜻이다. '34.1%의 예측이 틀렸다'는 뜻이 아니다. 20m 정책 자체의 적용 기준을 검사한 값으로, 30m로 학습한 모델과의 분포 차이 전체를 정량화한 것도 아니다.

첫 좌회전 예: 20m 조건의 frame48(route52.776m)에서 현재 지시는 Turn-06-L-S지만, 그 이전 2초 이력 전체에 걸쳐 적용 가능한 학습 지시는 아니다. 전환부에서 학습/추론 조건이 달라지는 구체적 사례다. 이력이 오래된 frame과 새 지시를 함께 보는 것 자체가 논리 오류인 것은 아니지만, 현재 sampler는 같은 조합을 학습시켜주지 않는다.

추가 관찰: epoch0 선택 창 448개 중 138개는 거리 지시였다. 거리 문장은 창 첫 frame 기준으로 계산되며, 창 마지막까지 평균 17.98m, 최대 36.74m 움직여도 같은 문장을 모든 frame loss에 사용한다. 발화 시점의 명령이라는 해석이면 유효할 수 있으므로 GT 오류라고 단정하지 않는다. 실시간의 발화/유지 시점과 학습 의미를 명시적으로 맞춰야 할 항목이다.

## 3. Last-token vs mean-token head 비교

동일 직진 subset: 기존 component 진단과 같은 train120 / held-out val33. 직진 정의는 모든 미래 GT가 전방이고 2.5초 전방>3m이며 모든 시점 abs(lateral)/max(forward,1)<0.0875. 단일 lap의 시간 분리이며 별도 lap 일반화 검증은 아니다.

Encoder·connector·LLM을 고정하고 각 frame의 마지막 유효 visual hidden 및 유효 visual hidden 평균을 추출했다. 텍스트·padding은 평균에서 제외했다. head 구조는 원래 2048→2048→10 MLP 그대로이며 기존 best head 가중치로 둘 다 시작했다. 출력 GT는 11개 frame의 원래 미래 좌표 전체다.

- 내부 fit85 / dev30, 시간 경계 4.5초 purge로 5개 제외. val33은 최적화와 checkpoint 선택에 사용하지 않음.
- Head만 FP32 학습. AdamW, weight_decay0.06, grad clip1, batch8, 400 update. raw-coordinate L1 그대로. seed607/608에서 같은 batch 순서를 last/mean에 적용.
- 학습률 1e-4를 먼저 시험하고, 원래 학습률 규모인 1e-5에서도 반복했다. 원래 전체 학습의 cosine schedule을 재현한 실험은 아니며 이 대조는 학습률 규모만 확인한다.
- 25 update마다 내부 dev ADE로 checkpoint 선택. step0도 후보에 포함. val은 선택된 checkpoint로만 최종 평가.

8개 조건 모두 내부 dev ADE 기준 최선이 step0이었다. 평균 readout의 1.886m와 last readout의 1.898m는 추가 학습으로 얻은 개선이 아니며 좌우 오차도 약0.904/0.902m로 비슷하다. 운영 모델을 평균 readout으로 바꿀 근거가 없다. 다른 목적함수, 더 넓은 데이터, 전체 LLM 공동학습의 모든 가능성을 부정하는 실험은 아니다.

원래 bf16 live readout val ADE 1.901169m, 같은 hidden에서 FP32 원래 head 1.897756m. Head 학습의 수치 정밀도 차이는 별도로 명시했다.

## 4. 좌우/전후 L1 gradient 비교

기존 마지막 토큰 hidden 및 원래 FP32 head에서 첫 fit8개 창(88개 frame)을 사용. L_way가 두 좌표의 평균이므로 각 축의 loss 기여는 axis MAE/2로 계산했다. 원래 connector/LLM 파라미터 전체의 backward를 측정한 것은 아니다.

| 항목 | 좌우 | 전후 |
|---|---:|---:|
| L_way 기여 | 0.312595 | 1.030992 |
| Head parameter gradient L2 | 9.855426 | 9.707108 |
| 입력 LLM hidden gradient L2 | 0.004096 | 0.008256 |

Head gradient cosine=0.003943. 전후 loss 값은 더 크지만 head gradient norm은 거의 같다. L1은 오차가 크다고 도함수 크기가 비례해서 커지는 loss가 아니다. 입력 hidden에서 전후 norm은 약2.02배이지만, 과거 reconstruction collapse처럼 수천 배 압도하는 상태는 이 측정에 없다. 이 결과로 다른 모듈의 gradient 경쟁까지 없다고 확정하지 않는다.

## 5. 작은 고정 데이터 학습 능력

Encoder·connector·LLM과 추출 hidden을 고정하고 처음 fit12개 창의 원래 head만 1,000 update 반복 학습. AdamW, weight_decay0, raw L1, clip1, 전체12창 batch. lr3e-4에서 cosine으로3e-6까지 감소. 새로운 architecture나 좌표 보정은 넣지 않았다.

| update | 전체 frame 좌표 L1(m) | 마지막 anchor ADE(m) | 마지막 anchor 2.5s 좌우 MAE(m) |
|---|---:|---:|---:|
| 0 | 1.3308 | 2.1449 | 0.6395 |
| 50 | 0.4579 | 0.6721 | 0.2473 |
| 100 | 0.4047 | 0.6794 | 0.3581 |
| 200 | 0.4036 | 0.6888 | 0.4270 |
| 500 | 0.2481 | 0.4926 | 0.2401 |
| 1000 | 0.1508 | 0.3550 | 0.2468 |

학습 loss는 1.331→0.151m, ADE는 2.145→0.355m로 감소했다. Gradient/update 경로가 끊겼거나 해당 입력에서 학습이 전혀 불가능한 상태는 아니다. 완전히 0까지 맞춘 것은 아니며, 전체 Stage 2 joint optimizer의 overfit 성공을 입증한 것도 아니다.

이 작은 묶음에 맞춘 뒤 val ADE는 2.487m로 원래 약1.898m보다 악화됐다. val 2.5초 좌우 오차는 0.701m로 줄었지만 전후 오차가 커져 전체 성능이 나빠졌다. 작은 장면 적합과 일반화는 다르며, head 추가 학습을 그대로 운영에 적용하면 안 된다.

## 다음 우선순위

1. **학습/실시간의 지시 이력 조건을 맞추는 단일 대조 실험을 우선한다.** 현재 frame의 지시를 사용하는 실제 추론 조건에 맞춰 이력은 유지하고, 해당 지시가 유효한 현재/후반 frame만 trajectory supervision하는 학습 방식과 기존 공통지시 방식의 비교가 후보이다. 모델에는 frame_loss_mask 지원이 있지만 현 dataset은 사용하지 않는다. 이 제안은 아직 적용하지 않았으며 loss mask와 지시 의미의 정합성을 먼저 정의해야 한다.
2. 30m 학습/20m 추론 차이는 위 조건 차이와 별도로 통제한다. 기존 sampler 자체의 불일치가 30m에서도 존재해 20m로 바꾼 것만이 원인은 아니다.
3. 이 수정으로 처음 직진의 오차가 반드시 해결된다는 증거는 없다. 직진의 남은 횡오차, frozen 표현의 한계, joint optimization 문제는 계속 남아 있다. 이번 결과만으로 encoder 또는 LLM 전체를 정상/불량으로 확정하지 않는다.

이번 작업은 검증이다. 운영 모델 가중치, 학습 config, loss, readout, navigation policy를 변경하지 않았다. UDP 제어 없음. GPU peak allocated는 frozen 특징 추출 3.097GiB, head-only 학습 0.153GiB. CPU2 thread로 제한. 임시 코드·가중치·특징·로그는 전용 .runtime/stage2_training_audit_20260920 폴더만 사용했으며 보고서 저장 후 삭제했고 폴더가 존재하지 않음을 확인했다.
