# MORAI vision encoder pretraining

This path preserves VLDrive's LMDrive encoder architecture and its connector
contract while intentionally not loading the public full LMDrive encoder.

## Model and labels

- Model: `memfuser_baseline_e1d3`
- RGB backbone: ImageNet-pretrained ResNet-50d
- LiDAR backbone, fusion transformer, decoder, queries, heads: trained on MORAI
- Route input during pretraining: local `target_point` derived from
  `x_command/y_command`
- Waypoint target: synchronized future Ego positions at dataset offsets
  `+5,+10,+15,+20,+25`
- Active losses: expert waypoint L1 and valid traffic-light cross entropy
- Disabled for this dataset: detection, actor velocity, stop-sign losses

The full runner keeps the public LMDrive schedule where it is applicable:
25 epochs, 5 warmup epochs, AdamW, weight decay 0.05, gradient clipping 5,
reference LR `7.5e-4`, and RGB-backbone reference LR `3e-4`.  LR is scaled by
the effective batch size (physical batch times gradient accumulation) over
512, because this workstation uses one GPU instead of the original
distributed setup.

The feature checkpoint is verified by strict-loading it into
`memfuser_baseline_e1d3_return_feature` and requiring `[B,106,256]` finite
output.  Global path target points are not used by that feature-only model.

## Signal-color-safe augmentation

MORAI training now defaults to `--rgb-hue-jitter 0`: brightness, contrast,
saturation and geometric augmentation remain unchanged, but hue does not turn
a red lamp green (or vice versa) while leaving its target label unchanged.
The encoder architecture, input sizes and deterministic inference transforms
are unchanged. This affects future training only; existing checkpoints and
token caches have not been repaired or regenerated by this setting.
Disabling a hue draw also changes later augmentation RNG draws: the other
augmentations retain their settings/distributions, not an exact replay of all
historical random choices.

Use `--rgb-hue-jitter 0.4` only for an explicit legacy-augmentation comparison.
The generic CARLA transform/loader defaults remain legacy-compatible. New
checkpoints record this option; resuming a recorded run with a different hue
setting is rejected in favor of a separate `--warm-start` run. Old checkpoints
without that provenance warn instead of claiming an exact augmentation resume.

The 2026-09-11 paired pixel audit reproduced the current legacy transform on
16 actual signal images and 32 fixed draws each: 110/512 changed directly
between red and green; with only hue disabled that count was 0/512. This is an
input-color audit, not a trained-model accuracy or driving-safety result.
The historical epoch25 checkpoint lacks the source/augmentation record needed
to prove its exact training configuration. See
[the controlled audit](../LAVIS/outputs/diagnosis_matched_exposure_20260911/traffic_hue_results.json).

## Preflight and training

The current RTX 5060 Ti requires a PyTorch build supporting Blackwell; the old
repository pin `torch==2.0.1` is not suitable.  The current WSL system Python
is 3.8 and has no PyTorch, so create a separate Python 3.10 environment before
the smoke test.  PyTorch 2.8/CUDA 12.8 is used here because it supports
Blackwell.  Ubuntu 20.04 cannot load the available `torch_scatter` wheel due
to its glibc requirement, so PointPillars automatically uses the equivalent
native PyTorch scatter reductions instead:

```bash
conda create -n vldrive-ve python=3.10 -y
source /opt/miniforge3/etc/profile.d/conda.sh
conda activate vldrive-ve
python -m pip install torch==2.8.0 torchvision==0.23.0 \
  --index-url https://download.pytorch.org/whl/cu128
python -m pip install -r requirements_morai.txt
```

The version choice is documented by the official
[PyTorch release matrix](https://pytorch.org/get-started/previous-versions/).
Verify the environment before starting a run:

```bash
python3 -c "import torch; print(torch.__version__, torch.version.cuda); print(torch.cuda.get_device_name()); print(torch.cuda.get_arch_list())"
```

Run the one-batch smoke test first:

```bash
cd /mnt/c/Users/autonav009/Desktop/AIMDrive/VLDrive/vision_encoder
bash scripts/smoke_morai.sh
```

Only after it succeeds, start the full run:

```bash
bash scripts/train_morai.sh
```

For a detached run that survives the terminal session and records its PID and
log, use:

```bash
bash scripts/start_morai_training.sh
tail -f output_morai/full_loop_expert/train.log
```

The full runner writes:

- `checkpoint-last.pth.tar`
- `model-best.pth.tar`
- `metrics.jsonl`
- `feature_contract.json`

The chronological validation split is useful for pipeline verification, but a
separate MORAI episode is required for a credible final generalization result.
